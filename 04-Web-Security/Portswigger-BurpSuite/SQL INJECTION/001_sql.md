# PortSwigger Web Security Academy – SQL Injection

## Lab: SQL injection vulnerability in WHERE clause allowing retrieval of hidden data

**Date:** 31 August 2026  
**Difficulty:** Apprentice  
**Category:** SQL Injection  


---

## What I learned

In this lab, the product category filter was vulnerable to SQL Injection.

The application was using a query similar to:

```sql
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
```

The `released = 1` condition means that normally only released products are displayed.

The goal of the lab was to manipulate the `category` parameter so that the application would also display unreleased products.

---

## How I solved it

I tested the category parameter and used this SQL Injection payload:

```text
'+OR+1=1--
```

The payload was inserted into the `category` parameter.

For example:

```text
/filter?category='+OR+1=1--
```

After submitting the request, the application displayed products that were normally hidden/unreleased, which solved the lab.

---

## Understanding the Payload

### `'`

The single quote closes the original SQL string.

The application originally has something similar to:

```sql
category = 'Gifts'
```

The `'` allows us to break out of the original value.

### `OR 1=1`

`1=1` is always true.

So the condition becomes effectively:

```sql
category = '' OR 1=1
```

Because `1=1` is true, the `WHERE` condition can match the products instead of restricting the results to one category.

### `--`

The `--` starts an SQL comment in the database used by the lab.

This comments out the remaining part of the original query, including:

```sql
AND released = 1
```

So the restriction that normally hides unreleased products is bypassed.

---

## Simplified Query

The original query was approximately:

```sql
SELECT * FROM products
WHERE category = 'Gifts'
AND released = 1
```

After injecting the payload, the query is effectively manipulated into something like:

```sql
SELECT * FROM products
WHERE category = ''
OR 1=1
--'
AND released = 1
```

The exact parsing depends on the database, but the important idea is that the injected condition becomes true and the remaining restriction is commented out.

## Burp Suite

The lab can be tested using **Burp Suite** by intercepting the request generated when selecting a product category.

The important parameter is:

```text
category
```

Example request:

```http
GET /filter?category=Gifts HTTP/2
```

Change the parameter to:

```http
GET /filter?category='+OR+1=1-- HTTP/2
```

Then forward the request and check the response/page for previously hidden products.
