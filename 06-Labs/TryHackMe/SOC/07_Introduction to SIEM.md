## What is SIEM?

A SIEM (Security Information and Event Management) solution collects logs from different devices across a network, stores them in one centralized location, normalizes the data into a common format, correlates related events, and generates alerts when suspicious activity is detected.

Instead of checking logs on every individual machine, analysts investigate everything from a single dashboard.

---

# SIEM Workflow

1. Collect logs from different log sources.
2. Normalize logs into a common format.
3. Correlate related events.
4. Detect suspicious activities using detection rules.
5. Generate alerts.
6. Investigate alerts and determine whether they are true or false positives.

---

# Types of Log Sources

## Host-Centric Logs

These logs are generated by the host itself.

Examples:

- User authentication
- File access
- Process execution
- Registry modifications
- PowerShell execution

Examples of devices:

- Windows
- Linux
- Servers

---

## Network-Centric Logs

These logs are generated when devices communicate across the network.

Examples:

- VPN connections
- SSH
- FTP
- HTTP/HTTPS traffic
- Firewall events
- IDS/IPS alerts

Examples of devices:

- Firewalls
- Routers
- IDS/IPS

---

# Challenges Without SIEM

Without a SIEM, analysts face several problems:

- Logs are spread across many devices.
- No centralized visibility.
- Different log formats.
- Difficult to correlate events.
- Manual analysis is time-consuming.
- Easy to miss important security events.

---

# Core Features of SIEM

## Centralized Log Collection

Collects logs from endpoints, servers, firewalls, and other devices into one place.

---

## Log Normalization

Converts logs from different formats into a consistent structure, making them easier to search and analyze.

---

## Log Correlation

Connects related events from multiple systems to detect suspicious activity that may not be obvious when viewing logs individually.

---

## Real-Time Alerting

Triggers alerts when predefined detection rules are matched.

Example:

- Multiple failed login attempts
- Successful login after multiple failures
- Event log clearing
- USB device insertion
- Large outbound data transfers

---

## Dashboards

Provides an overview of:

- Alerts
- Top event IDs
- Process activity
- Network connections
- MITRE ATT&CK techniques
- System health

# Detection Rules

Detection rules are logical conditions that generate alerts when suspicious activity is detected.

Example:

```text
IF EventID = 4688
AND ProcessName contains "whoami"
THEN Generate Alert
```

Another example:

```text
IF EventID = 104
THEN Generate Alert "Event Logs Cleared"
```

---

# Alert Investigation Process

When an alert is generated:

1. Review the triggered rule.
2. Examine related events.
3. Determine whether it is a True Positive or False Positive.
4. Investigate affected systems.
5. Take appropriate response actions.

Possible actions include:

- Contact asset owner
- Isolate infected host
- Block malicious IP
- Tune noisy detection rules
