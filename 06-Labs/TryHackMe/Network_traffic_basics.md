# Overview

This room introduced the fundamentals of **Network Traffic Analysis (NTA)**. Instead of relying only on logs generated by firewalls, servers, or endpoint devices, network traffic analysis allows us to inspect the actual packets traveling across the network. By analyzing packet contents, we can detect attacks, investigate incidents, validate security alerts, and understand how communication occurs between devices.

---

# Task 2 - What is the Purpose of Network Traffic Analysis?

## What is Network Traffic Analysis?

Network Traffic Analysis (NTA) is the process of capturing, inspecting, and analyzing network packets to understand how devices communicate and to identify suspicious or malicious activity.

Unlike traditional logs, packet analysis provides visibility into the **actual content** of network communications.

---

## DNS Tunneling Scenario

In this scenario, an SOC analyst received an alert because a host named **WIN-016** was generating an unusually high number of DNS requests.

Example log:

```text
2025-10-03 09:15:23 SRC=192.168.1.16 QUERY=aj39skdm.malicious-tld.com
2025-10-03 09:15:31 SRC=192.168.1.16 QUERY=msd91azx.malicious-tld.com
2025-10-03 09:15:45 SRC=192.168.1.16 QUERY=cmd01.malicious-tld.com
```

From firewall logs we can determine:

- Source IP
- Destination domain
- Query type
- Timestamp

However, logs alone cannot reveal the **actual contents** of the DNS responses.

Packet inspection revealed that TXT records contained encoded Command and Control (C2) instructions.

Example:

```text
TXT: "SSBsb3ZlIHlvdXIgY3VyaW91c2l0eQ=="
```

This demonstrates how attackers can use **DNS tunneling** to communicate with compromised systems while avoiding detection.

---

## Why Analyze Network Traffic?

Network traffic analysis helps to:

- Monitor network performance
- Detect abnormal traffic patterns
- Inspect suspicious communications
- Identify malware activity
- Detect data exfiltration
- Investigate incidents
- Validate security alerts
- Reconstruct attacks during incident response

---

## Key Concept

Logs show **what happened**, while packet captures show **how it happened**.

# Task 3 - What Network Traffic Can We Observe?

Network traffic can be observed across every layer of the TCP/IP model.

---

## 1. Application Layer

This layer contains:

- Application headers
- Payload (actual data)

Example:

HTTP Request

```http
GET /downloads/suspicious_package.zip HTTP/1.1
```

HTTP Response

```http
Content-Type: application/zip
Content-Length: 10485760
```

Logs usually contain only the HTTP headers.

Only packet captures reveal the downloaded ZIP file itself.

### Answer

ZIP size:

```
10485760 bytes
```

---

## 2. Transport Layer

Responsible for:

- TCP
- UDP

Important information includes:

- Source Port
- Destination Port
- Flags
- Sequence Numbers
- Acknowledgement Numbers

Example:

```
SYN
SYN ACK
ACK
```

This forms the **TCP Three-Way Handshake**.

---

### Detecting Session Hijacking

An attacker attempting to inject packets into an existing TCP session often uses abnormal **sequence numbers**.

Example:

```
Seq = 34567232
```

Large unexpected jumps may indicate session hijacking.

### Answer

```
Sequence Number
```

---

## 3. Internet Layer

Contains:

- Source IP
- Destination IP
- TTL
- Fragment Offset

Packet fragmentation occurs when packets exceed the MTU.

Attackers abuse fragmentation by creating:

- Tiny fragments
- Overlapping fragments

These techniques may bypass Intrusion Detection Systems (IDS).

### Answer

```
Fragmentation
```

---

## 4. Link Layer

Contains:

- Source MAC Address
- Destination MAC Address

Packet captures help detect attacks such as:

- ARP Poisoning
- MAC Spoofing

Example:

```
192.168.1.10 is at aa:bb:cc:dd:ee:ff
```

The attacker falsely associates their MAC address with another device's IP address.

---

## Summary of TCP/IP Layers

| Layer | Information Available | Example Attack |
|--------|----------------------|----------------|
| Application | HTTP, DNS, Payload | DNS Tunneling |
| Transport | TCP/UDP, Ports, Sequence Numbers | Session Hijacking |
| Internet | IP, TTL, Fragment Offset | Fragmentation Attack |
| Link | MAC Addresses, ARP | ARP Poisoning |

# Task 4 - Network Traffic Sources and Flows

Network traffic originates from two primary sources.

---

## Network Traffic Sources

### 1. Intermediary Devices

Devices through which traffic passes.

Examples:

- Firewalls
- Routers
- Switches
- IDS
- IPS
- Web Proxies
- Wireless Controllers

These devices mainly generate management traffic.

---

### 2. Endpoint Devices

Devices where communication starts and ends.

Examples:

- Workstations
- Servers
- Mobile Phones
- Printers
- IoT Devices
- Cloud Resources

Endpoint devices generate most of the network traffic.

### Answer

```
Endpoint
```

# Network Traffic Flows

Traffic can be grouped into two categories.

---

## North-South Traffic

Traffic entering or leaving the organization's network.

Examples:

- HTTPS
- DNS
- SSH
- VPN
- SMTP
- RDP

This traffic passes through the firewall.

---

## East-West Traffic

Traffic that remains inside the organization's network.

Examples:

- Active Directory
- SMB
- Kerberos
- File Sharing
- Database Communication

Attackers frequently use East-West traffic for **lateral movement**.

---

## HTTPS Flow

HTTPS traffic often passes through:

```
Host
 ↓
Firewall
 ↓
Web Proxy
 ↓
Internet
 ↓
Web Server
```

The proxy performs TLS inspection before forwarding the traffic.

---

## DNS Flow

Typical DNS communication:

```
Host
 ↓
Internal DNS
 ↓
Firewall
 ↓
External DNS Server
```

The internal DNS server queries external DNS servers on behalf of clients.

---

## SMB with Kerberos

Before an SMB connection can be established:

```
Host
 ↓
Domain Controller
 ↓
Kerberos Authentication
 ↓
SMB File Server
```

Kerberos provides the authentication ticket before file sharing begins.

### Answer

```
Kerberos
```

# Task 5 - How Can We Observe Network Traffic?

There are three primary ways to observe network activity.

---

## 1. Logs

Every system generates logs.

Examples include:

- Windows Event Logs
- Linux Syslog
- Apache Access Logs

Logs provide useful metadata but usually do not contain full packet contents.

---

## 2. Full Packet Capture (PCAP)

Packet captures allow analysts to inspect every field inside a network packet.

Two common methods are used.

### Network TAP

A hardware device installed inline with the network.

Characteristics:

- Copies all packets
- No noticeable delay
- Operates at Layer 2
- Does not require an IP address

---

### Port Mirroring (SPAN)

A switch duplicates packets from one interface to another monitoring port.

Example Cisco configuration:

```bash
monitor session 1 source interface fastEthernet0/1
monitor session 1 destination interface fastEthernet0/2
```

Cloud platforms also support traffic mirroring, such as AWS VPC Traffic Mirroring.

---

## Packet Capture Best Practices

Consider:

- Correct placement of the TAP or mirror
- Storage requirements
- Capture duration
- Performance impact

Example:

Capturing traffic on a **1 Gbps** link for one day can require approximately **10.8 TB** of storage.

---

## Packet Analysis Tools

Common tools include:

- Wireshark
- TCPdump
- Snort
- Suricata
- Zeek

Future rooms in this module focus primarily on **Wireshark**.

---

## 3. Network Statistics

Instead of storing every packet, metadata about traffic flows can be collected.

Examples:

### NetFlow

Developed by Cisco.

Collects metadata such as:

- Source IP
- Destination IP
- Ports
- Bytes transferred
- Duration

Useful for detecting:

- Data exfiltration
- Command and Control
- Lateral movement

---

### IPFIX

Vendor-neutral successor to NetFlow.

Advantages:

- More flexible
- Supported by multiple vendors
- Allows custom field collection
