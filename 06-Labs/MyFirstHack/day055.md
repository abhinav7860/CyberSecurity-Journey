## Overview

Day 55 introduces one of the most important ideas in Linux command-line work: **combining small commands**.

Linux commands are designed to do focused jobs:

- `grep` → find matching text
- `wc` → count
- `sort` → sort output
- `uniq` → remove adjacent duplicates
- `head` → show the beginning
- `tail` → show the end

The **pipe (`|`)** connects these commands so the output from one becomes the input of another.

**Main idea:**

> Instead of looking for one command that does everything, combine small commands to answer a specific question.

This is especially useful in cybersecurity because large amounts of log data can be filtered, counted, sorted, and summarised quickly.

---

# 1. The Pipe `|`

The pipe is written as:

```bash
|
```

It takes the **output of the command on the left** and sends it as **input to the command on the right**.

### Basic structure

```bash
command1 | command2
```

Example:

```bash
grep "failed" auth.log | wc -l
```

### What happens?

```text
auth.log
   │
   ▼
grep "failed"
   │
   │ failed-login lines
   ▼
wc -l
   │
   ▼
number of failed logins
```

Instead of displaying every matching line, `wc -l` counts them.

### Why this is powerful

Neither command alone answers the question:

> "How many failed login attempts are in this log?"

But together:

```bash
grep "failed" auth.log | wc -l
```

they do.

---

# 2. Pipelines Can Have Multiple Commands

A pipeline does not have to contain only two commands.

You can connect several commands:

```bash
command1 | command2 | command3 | command4
```

The output flows from left to right.

```text
Command 1
   │
   ▼
Command 2
   │
   ▼
Command 3
   │
   ▼
Command 4
```

Each command performs one small transformation.

For example:

```bash
grep "error" logfile | sort | uniq
```

This can:

1. Find lines containing `error`
2. Sort them
3. Remove adjacent duplicate lines

The important mindset is:

```text
Question
   ↓
Break it into small steps
   ↓
Choose a command for each step
   ↓
Connect them with |
```

# 3. Redirection

A pipe sends output to **another command**.

Redirection sends output to a **file**.

The main operators are:

```bash
>
>>
```

---

## `>` — Write / Overwrite

Example:

```bash
ls -la > results.txt
```

This sends the output of `ls -la` into `results.txt`.

If `results.txt` already exists, its previous contents are **overwritten**.

```text
ls -la
   │
   ▼
results.txt
```

### Important

Be careful with:

```bash
>
```

because it replaces the existing contents of the destination file.

---

# 4. `>>` — Append

The double greater-than operator adds output to the **end** of an existing file.

Example:

```bash
echo "New event" >> log.txt
```

Existing contents stay intact, and the new output is added at the bottom.

### Difference

| Operator | Behaviour |
|---|---|
| `>` | Write / overwrite |
| `>>` | Append |

Easy way to remember:

```text
>   = replace
>>  = add
```

This distinction is important when preserving investigation results or logs.

---

# 5. Pipe vs Redirection

| Method | Destination |
|---|---|
| Normal command output | Screen |
| `|` | Another command |
| `>` | File, overwriting it |
| `>>` | File, appending to it |

Example:

```bash
grep "failed" auth.log
```

Output → screen

```bash
grep "failed" auth.log | wc -l
```

Output → another command

```bash
grep "failed" auth.log > failed.log
```

Output → file

```bash
grep "failed" auth.log >> investigation.log
```

Output → appended to file

# 6. Useful Commands for Pipelines

## `wc`

`wc` counts information.

Most commonly:

```bash
wc -l
```

`-l` means **lines**.

Example:

```bash
grep "failed" auth.log | wc -l
```

This answers:

> How many matching lines are there?

---

## `sort`

`sort` arranges lines into order.

Example:

```bash
cat errors.txt | sort
```

It can be useful before `uniq` when repeated values need to be grouped together.

---

## `uniq`

`uniq` removes **adjacent duplicate lines**.

Example:

```bash
sort errors.txt | uniq
```

Using `sort` first is useful because identical lines become adjacent.

---

## `head`

`head` shows the first lines of input.

Example:

```bash
grep "error" logfile | head
```

This can quickly show the first few matching results.

---

## `tail`

`tail` shows the last lines.

Example:

```bash
grep "error" logfile | tail
```

Useful when you want the latest part of the filtered output.

# 7. Building Pipelines from Questions

The important skill is not memorising random pipelines.

Start with a question.

### Question 1

**How many times did an IP address appear in a log?**

Break it down:

```text
Find lines containing the IP
        ↓
      grep
        ↓
Count the lines
        ↓
      wc -l
```

Example:

```bash
grep "192.168.1.10" auth.log | wc -l
```

---

### Question 2

**What are the unique error messages?**

Break it down:

```text
Find errors
   ↓
grep
   ↓
Sort them
   ↓
sort
   ↓
Remove duplicates
   ↓
uniq
```

Example:

```bash
grep "error" logfile | sort | uniq
```

---

### Question 3

**Show only the first few matching results**

```bash
grep "failed" auth.log | head
```

---

### Question 4

**Save matching results for later investigation**

```bash
grep "failed" auth.log > failed_logins.txt
```

This is useful because the results can be reviewed later or included in investigation notes.

# 8. Security / SOC Use

Pipes and redirection are especially useful for cybersecurity investigations.

Large logs can contain thousands or millions of entries.

Instead of manually reading everything:

```text
Large Log
   │
   ▼
grep → filter relevant events
   │
   ▼
sort → organise results
   │
   ▼
uniq → remove duplicates
   │
   ▼
wc → count
   │
   ▼
Useful result
```

For example:

```bash
grep "failed" auth.log | wc -l
```

can quickly give the number of failed login events.

A more complex investigation may involve:

```text
Extract
  ↓
Filter
  ↓
Sort
  ↓
Deduplicate
  ↓
Count
  ↓
Summarise
```

This is similar to the packet-filtering mindset from the networking phase: instead of analysing everything, reduce the data to the parts that matter.

# 9. Preserving Investigation Results

Redirection can help keep command output as evidence or investigation notes.

Example:

```bash
grep "failed" auth.log > failed_logins.txt
```

Now the matching results are stored in:

```text
failed_logins.txt
```

You can later inspect it with:

```bash
less failed_logins.txt
```

Or append additional findings:

```bash
grep "error" system.log >> investigation.txt
```

### Important distinction

If you want to preserve previous results:

```bash
>>
```

If you intentionally want to replace the file:

```bash
>
```

# 10. The Composing Mindset

The biggest lesson of Day 55 is not just the `|` character.

It is learning to **compose commands**.

A beginner may think:

> "Is there one command that does all of this?"

A more experienced Linux user thinks:

> "What simple steps do I need, and which commands can perform them?"

For example:

```text
Question:
Which events are repeated most often?

        ↓

Find relevant lines
        ↓
      grep
        ↓
Sort them
        ↓
      sort
        ↓
Remove duplicates
        ↓
      uniq
```

The command line becomes a language where commands can be combined to express increasingly complex questions.

# 12. Quick Revision

### Pipe

```bash
command1 | command2
```

Output of command 1 → input of command 2.

### Write to a file

```bash
command > file.txt
```

Overwrites the file.

### Append to a file

```bash
command >> file.txt
```

Adds to the end of the file.

### Count matching lines

```bash
grep "failed" auth.log | wc -l
```

### Sort and remove duplicates

```bash
grep "error" logfile | sort | uniq
```

### Save results

```bash
grep "failed" auth.log > failed.txt
```
