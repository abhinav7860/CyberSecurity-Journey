## 1. Introduction

Yesterday I learned about the **Kill Chain**, which gave me the big-picture view of how an attack progresses from reconnaissance to the final objective.

Today I zoomed in.

The Kill Chain is useful because it shows the broad stages of an attack, but it does not describe every specific way an attacker can perform those stages. **MITRE ATT&CK** provides that deeper level of detail.

The main idea I took from this lesson is:

> **The Kill Chain gives me the big picture, while MITRE ATT&CK gives me the specific tactics and techniques attackers use.**

ATT&CK is a widely used cybersecurity knowledge base built from observations of real-world attacker behaviour. It provides a structured and public catalogue of attacker techniques and is used across security tools, threat reports, defensive teams, red teams, blue teams, and security jobs.

---

# 2. From Stages to Specifics

The Kill Chain describes attacks at a relatively high level.

For example, it may tell me:

```text
The attacker installs persistence
```

But that does not tell me **how** the attacker established persistence.

There could be many specific methods:

```text
Persistence
    ↓
Scheduled Task
    ↓
New Account
    ↓
Other Persistence Techniques
```

This is where ATT&CK becomes useful.

A simple comparison is:

```text
KILL CHAIN
    ↓
Big Picture
    ↓
Attack Stages

MITRE ATT&CK
    ↓
Detailed Picture
    ↓
Tactics + Techniques
```

The lesson described this as the difference between knowing the **chapters of the attacker's playbook** and knowing the **individual plays** inside those chapters.

---

# 3. What Is MITRE ATT&CK?

**MITRE ATT&CK** is a knowledge base that documents how real attackers behave.

It is:

- Based on real-world observations.
- Organised into a structured framework.
- Publicly available.
- Maintained by the non-profit organisation MITRE.
- Focused on attacker tactics and techniques.

This is important because ATT&CK is not simply a theoretical list of possible attacks.

It represents documented knowledge about techniques that have been observed in real attacks.

The framework turns scattered knowledge about attacker behaviour into a common reference that security professionals can use.

---

# 4. Why ATT&CK Is So Detailed

The Kill Chain has seven broad stages.

ATT&CK goes much deeper.

The lesson explains that ATT&CK contains **hundreds of documented techniques**, with each technique describing a specific way attackers operate.

For example:

```text
Kill Chain:
Installation

        ↓

ATT&CK:
Specific persistence techniques
        ↓
Scheduled Task
New Account
Other documented methods
```

This level of detail is useful because defenders need to know what they should actually look for.

Knowing that an attacker wants persistence is useful.

Knowing the **specific techniques used to establish persistence** is much more actionable for detection and defence.

# 5. Tactics and Techniques

The two most important concepts I learned today are:

1. **Tactics**
2. **Techniques**

The easiest way for me to remember the difference is:

```text
TACTIC = WHY
TECHNIQUE = HOW
```

# 6. What Is a Tactic?

A **tactic** represents the attacker's goal or intention.

It answers:

> **"What is the attacker trying to achieve?"**

The lesson introduced tactics such as:

- Initial Access
- Execution
- Persistence
- Privilege Escalation
- Defence Evasion
- Credential Access
- Discovery
- Lateral Movement
- Collection
- Command and Control
- Exfiltration
- Impact

Each tactic represents a category of attacker intent.

For example:

```text
Persistence
    ↓
Attacker's goal:
Maintain access
```

Or:

```text
Credential Access
    ↓
Attacker's goal:
Obtain credentials
```

So tactics describe the **purpose** behind attacker activity.

---

# 7. What Is a Technique?

A **technique** is a specific method used to achieve a tactic.

It answers:

> **"How is the attacker going to achieve that goal?"**

For example:

```text
TACTIC
Persistence

    ↓

TECHNIQUES
Scheduled Task
New Account
Other persistence methods
```

The tactic is the purpose.

The technique is the actual move.

There can be many techniques under the same tactic because attackers can achieve the same goal in different ways.

---

# 8. Tactic vs Technique

This is the most important distinction I want to remember from this lesson.

| Concept | Meaning | Question |
|---|---|---|
| Tactic | Attacker's goal | Why? |
| Technique | Specific method | How? |

### Example

```text
Why?
↓
Persistence
↓
How?
↓
Scheduled Task
```

Another example:

```text
Why?
↓
Credential Access
↓
How?
↓
A specific credential-stealing technique
```

This two-level structure makes the huge amount of attacker behaviour easier to organise and understand.

# 11. How Defenders Actually Use ATT&CK

One of the most important things I learned is that ATT&CK is **not just something to read**.

It is a working tool used in defensive security.

There are several important ways defenders use it.

---

# 12. Detection Coverage

The first major use is **detection coverage**.

A security team can go through ATT&CK techniques and ask:

> **"Would we detect this if an attacker used it?"**

This changes a vague question such as:

```text
"Are we secure?"
```

into a much more concrete question:

```text
Technique
    ↓
Do we detect it?
    ↓
YES / NO
```

If a team discovers that it cannot detect certain techniques, those techniques represent potential **blind spots**.

The team can then work on improving detection coverage.

---

# 13. ATT&CK Coverage Maps

Security teams can build coverage maps showing which ATT&CK techniques their security controls can detect.

A simplified example:

```text
ATT&CK Technique
       ↓
Detection Available?
       ↓
 ┌───────────────┐
 │      YES      │
 │   Detected    │
 └───────────────┘

or

 ┌───────────────┐
 │       NO      │
 │    Blindspot  │
 └───────────────┘
```

This gives security teams a systematic way to understand their visibility instead of relying only on assumptions.

---

# 14. ATT&CK as a Common Language

Another major use of ATT&CK is providing a **common language**.

Without a shared framework, different teams and tools might describe the same attacker behaviour in different ways.

ATT&CK provides:

- Standard technique names
- Standard identifiers
- A shared structure
- Consistent terminology

This makes communication easier between:

- SOC teams
- Threat intelligence teams
- Security tools
- Security researchers
- Red teams
- Blue teams
- Organisations

For example, when a threat report references a specific ATT&CK technique, defenders can immediately understand the type of behaviour being described and investigate whether their own environment can detect it.

---

# 15. ATT&CK and Threat Intelligence

ATT&CK is also useful for **threat intelligence**.

The framework documents techniques associated with specific real-world attacker groups.

This allows defenders to ask:

```text
Which attackers are relevant to our organisation?
             ↓
What techniques are they known to use?
             ↓
Can we detect those techniques?
             ↓
Where are our gaps?
```

This helps security teams focus their defensive efforts on attacker behaviours that are relevant to their environment.

---

# 16. ATT&CK and Attack Emulation

ATT&CK is also useful for testing security controls.

### Red Team

Red teams can use ATT&CK techniques to emulate real attacker behaviour.

```text
ATT&CK Technique
       ↓
Red Team
       ↓
Emulate Technique
```

### Blue Team

Blue teams can then check whether their security controls detect that activity.

```text
Red Team Activity
       ↓
Security Monitoring
       ↓
Blue Team Detection
```

This creates a structured way to test and improve security.

Instead of performing random offensive activity, teams can use documented attacker techniques as a shared reference.

# 17. ATT&CK and the Kill Chain Together

A major takeaway from this lesson is that **MITRE ATT&CK and the Kill Chain are complementary**.

They are not replacements for one another.

They describe attacks at different levels of detail.

```text
                 ATTACK

        ┌─────────────────────┐
        │     KILL CHAIN      │
        │                     │
        │   Big Picture       │
        │   Attack Stages     │
        └──────────┬──────────┘
                   ↓
        ┌─────────────────────┐
        │    MITRE ATT&CK     │
        │                     │
        │ Detailed Tactics    │
        │        +            │
        │ Detailed Techniques │
        └─────────────────────┘
```
