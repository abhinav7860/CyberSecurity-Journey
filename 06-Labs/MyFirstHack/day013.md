# Key Concepts

## What is a Cookie?
- A cookie is a small text file stored by the browser.
- It allows websites to remember users between requests.
- Common uses:
  - Keeping users logged in
  - Saving shopping carts
  - Remembering preferences

> The web is **stateless**, so cookies give it "memory".

---

## Cookie Structure

A cookie usually contains:

- **Name**
- **Value**
- **Expires / Max-Age**
- **Secure**
- **HttpOnly**
- **SameSite**

Example:

```text
session_id=a8f3kp29d1xq7b4m
```

The value is usually a random identifier that points to my session stored on the server.

---

## Session Cookies

Session cookies are the most important cookies.

If the server receives a valid session cookie, it treats the request as coming from the logged-in user.

This means:

- Password is **not** checked on every request.
- The session cookie is the proof that I'm already authenticated.

> Whoever has the session cookie is treated as the logged-in user.

---

## Cookie Security Flags

### Secure
- Cookie is only sent over HTTPS.

### HttpOnly
- JavaScript cannot access the cookie.
- Helps protect against XSS attacks.

### SameSite
- Protects against CSRF attacks.
- Controls when browsers send cookies to other websites.

### Expires / Max-Age
- Determines how long the cookie remains valid.

# Practical

## Task 1 - Inspect Cookies

### Website
Gmail

### Observations

- Viewed cookies using DevTools → Application → Cookies.
- Found authentication-related cookies such as:
  - `__Secure-1PSID`
  - `__Secure-3PSID`
  - `__Host-GMAIL_SCH_GML`
- Most important cookies had:
  -  Secure
  -  HttpOnly
  -  SameSite (Lax / Strict / None depending on the cookie)

### What I learned

Large websites protect authentication cookies using multiple security flags.

---

## Task 2 - Watch Cookies Travel

### Website
GitHub

### What I did

- Opened DevTools → Network.
- Enabled **Preserve Log**.
- Observed login-related requests.

### Findings

- Saw the server sending cookies using the **Set-Cookie** response header.
- Later requests automatically included the **Cookie** request header.
- Security flags like Secure and HttpOnly were also present.

### What I learned

Login works like this:

```
Login
      ↓
Server sends Set-Cookie
      ↓
Browser stores cookie
      ↓
Browser automatically sends Cookie on every future request
```

This is how websites remember authenticated users.

---

## Task 3 - Edit a Session Cookie

### Website
Pinterest

### Cookie Edited

```
_pinterest_sess
```

### What I did

- Opened Cookie-Editor.
- Located the session cookie.
- Changed **one character** in the cookie value.
- Saved the changes.
- Refreshed the page.

### Result

 Pinterest immediately logged me out.

### Why?

Changing even one character made the session cookie invalid.

The server could no longer match my session, so it treated me as a new user and redirected me to log in again.

### Biggest takeaway

One small random-looking string is the difference between:

```
Logged In 

and

Logged Out 
```

# What I Learned

- Cookies allow websites to remember users.
- Session cookies are used for authentication.
- Browsers automatically send cookies with every request.
- Cookie security depends on flags like:
  - Secure
  - HttpOnly
  - SameSite
- If a session cookie is stolen, an attacker may access the account without knowing the password.
- Editing a session cookie proves how websites rely entirely on that value to identify authenticated users.

## Important Terms

| Term | Meaning |
|------|---------|
| Cookie | Small text stored by browser |
| Session Cookie | Identifies logged-in user |
| Set-Cookie | Server sends cookie to browser |
| Cookie Header | Browser sends stored cookie back |
| Secure | HTTPS only |
| HttpOnly | Blocks JavaScript access |
| SameSite | Helps prevent CSRF |
| Session Hijacking | Using someone else's session cookie to impersonate them |

## Revision Notes

- Cookies = Website memory.
- Session cookie = Identity proof.
- Password is checked once.
- Cookie is checked on every request.
- Secure + HttpOnly + SameSite are essential security flags.
- Changing the session cookie immediately invalidates the session.
