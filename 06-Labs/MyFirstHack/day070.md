## 2. Encryption vs Hashing

### Encryption

Encryption is used when I need to protect information from being read by unauthorised people and later recover the original information.

```text
Plaintext
    ↓
Encryption + Key
    ↓
Ciphertext
    ↓
Decryption + Key
    ↓
Plaintext
```

### Hashing

Hashing is designed to create a fingerprint of data.

```text
Input
   ↓
Hash Function
   ↓
Hash / Digest
```

The important difference is:

```text
Encryption → Reversible
Hashing    → One-way
```

Hashing is not meant to recover the original input.

---

## 3. Why Use One-Way Math?

At first, I wondered why anyone would deliberately use a technique that cannot be reversed.

The answer is that hashing is not trying to hide a secret that I will later recover.

It is mainly used for:

1. **Verifying integrity**
2. **Protecting passwords**

For these purposes, being one-way is an advantage.

```text
Encryption:
"I need to recover the original data."

Hashing:
"I need to verify or compare the data."
```

---

## 4. What Is a Hash?

A hash function takes an input and produces a **fixed-length string** called a hash or digest.

The input can be:

- A word
- A sentence
- A file
- An entire database
- Other data

```text
Any Input
    |
    v
Hash Function
    |
    v
Fixed-Length Hash
```

The same input always produces the same hash when the same hash function is used.

---

## 5. Properties of a Good Hash Function

### 5.1 Deterministic

The same input always produces exactly the same hash.

```text
Input
  ↓
Hash
  ↓
Same result every time
```

This is important because I can hash something again later and compare the result.

---

### 5.2 Fixed-Length

No matter how large or small the input is, a particular hash algorithm produces an output of its defined length.

```text
Small Input ──┐
              ├──> Hash Function ──> Fixed-Length Hash
Large Input ──┘
```

---

### 5.3 One-Way

A hash can be calculated easily from the input, but it should not be feasible to work backwards from the hash to recover the original input.

```text
Input
  |
  v
Hash
  |
  X
No practical reversal
```

This is the defining property of hashing.

---

### 5.4 Collision Resistance

A collision happens when two different inputs produce the same hash.

A good cryptographic hash function is designed so that this is extraordinarily unlikely.

```text
Input A ──> Hash A
Input B ──> Hash B

Input A ≠ Input B
        ↓
Hash A should ≠ Hash B
```

---

## 6. Avalanche Effect

The **avalanche effect** means that even a tiny change in the input can produce a completely different hash.

For example:

```text
Input 1:
Hello

Input 2:
hello
```

Only one character changed, but the resulting hashes should be dramatically different.

```text
Hello
  ↓
Hash A

hello
  ↓
Completely different Hash B
```

This makes hashing a sensitive detector of tampering.

```text
Tiny Change
    ↓
Completely Different Hash
    ↓
Change Becomes Obvious
```

---

## 7. Hash as a Digital Fingerprint

The easiest way for me to think about a hash is as a **digital fingerprint**.

```text
Original Data
      |
      v
 Hash Function
      |
      v
Digital Fingerprint
```

If the data changes:

```text
Original Data
      |
      X
Changed Data
      |
      v
Different Fingerprint
```

The fingerprint is not meant to reconstruct the original data.

It is meant to help me determine whether the data still matches what I expect.

# 8. Use One — Verifying Integrity

The first major use of hashing is verifying **integrity**.

Integrity is one of the CIA Triad properties I studied on Day 66.

The basic process is:

```text
Original Data
     |
     v
Hash Function
     |
     v
Original Hash
```

Later:

```text
Current Data
     |
     v
Hash Function
     |
     v
Current Hash
```

Then I compare them.

### Hashes match

```text
Original Hash = Current Hash
        ↓
Data is unchanged
```

### Hashes differ

```text
Original Hash ≠ Current Hash
        ↓
Data changed
        ↓
Investigate
```

---

## 9. Software Download Verification

A common example is verifying downloaded software.

The software publisher can provide the expected hash:

```text
software.zip
SHA-256: [published hash]
```

I download the file and calculate its hash.

```text
Downloaded File
      |
      v
Hash Function
      |
      v
My Hash
```

Then:

```text
Published Hash
      |
      | Compare
      v
My Hash
```

If they match, the downloaded file is bit-for-bit identical to the published file.

If they do not match, the file may have been corrupted or tampered with.

This connects with the suspicious-file investigation I performed on Day 56.

---

## 10. File Integrity Monitoring

Hashing can be used for **File Integrity Monitoring (FIM)**.

I can record the expected hash of an important file:

```text
Known Good File
      |
      v
Known Good Hash
      |
      v
Store Hash
```

Later:

```text
Current File
      |
      v
Calculate Hash
      |
      v
Compare with Stored Hash
```

If the hashes differ:

```text
Hash Mismatch
      ↓
File Changed
      ↓
Investigate
```

This can help detect an attacker modifying important system files.

---

## 11. Forensics and Evidence

Hashing is also useful in digital forensics.

This connects directly with my Day 65 Linux Forensics investigation.

An investigator can hash an evidence file and record the hash.

```text
Evidence
   |
   v
Hash
   |
   v
Recorded Hash
```

Later, the evidence can be hashed again:

```text
Evidence
   |
   v
New Hash
   |
   v
Compare with Recorded Hash
```

If the hashes match, this provides evidence that the file has not changed since the recorded hash was created.

The hash therefore acts like a **tamper-evident fingerprint**.

---

## 12. Backup Verification

The same concept can be used to verify backups.

```text
Original Data
     |
     v
Hash
     |
     v
Backup
```

Later:

```text
Backup
   |
   v
Hash Again
   |
   v
Compare
```

If the hashes match, the backup is consistent with the expected data.

---

## 13. Why One-Way Hashing Is Useful for Integrity

For integrity verification, I do not need to recover the original data from the hash.

I only need to compare two fingerprints.

```text
Expected Hash
      |
      | Compare
      v
Current Hash
```

Therefore:

```text
No reversal needed
        ↓
One-way hashing is ideal
```

This helped me understand why hashing should not be confused with encryption.

# 14. Use Two — Protecting Passwords

The second major use of hashing is **password protection**.

A website needs to verify a password when I log in.

But storing actual passwords is dangerous.

If a database stores plaintext passwords:

```text
username     password
--------     --------
user1        mypassword
user2        password123
user3        qwerty
```

a database breach could expose the actual passwords immediately.

---

## 15. Storing Password Hashes

Instead of storing the original password, a properly implemented system stores a value derived from it using an appropriate password-hashing scheme.

Conceptually:

```text
User Password
      |
      v
Password Hashing
      |
      v
Stored Hash
```

When I log in:

```text
Password I Enter
       |
       v
Password Hashing
       |
       v
New Hash
       |
       v
Compare with Stored Hash
```

If the verification succeeds:

```text
Password Hash
      =
Stored Password Hash
      ↓
Password Verified
```

The system does not need to store my original password just to verify it.

---

## 16. Why One-Way Hashing Helps Password Security

If a password database containing plaintext passwords is breached:

```text
Database Breach
      ↓
Actual Passwords Exposed
```

If the database contains password hashes:

```text
Database Breach
      ↓
Password Hashes Exposed
```

The attacker cannot simply reverse the hashes to obtain the original passwords.

This is why storing passwords in plaintext is considered a serious security failure.

---

## 17. Hashing Does Not Make Weak Passwords Safe

There is an important limitation.

Attackers can guess passwords.

For example:

```text
Guess:
password123
      |
      v
Hash the Guess
      |
      v
Compare with Stolen Hash
```

They can repeat this with many likely passwords.

Therefore:

```text
Weak Password
      +
Password Hashing
      ≠
Automatically Safe
```

Strong passwords still matter.

---

## 18. Salting

A **salt** is additional random data added to a password before hashing.

Conceptually:

```text
Password + Random Salt
          |
          v
      Hash Function
          |
          v
       Password Hash
```

This helps ensure that identical passwords do not necessarily produce identical stored hashes.

For example:

```text
User A:
Password + Salt A
       ↓
     Hash A


User B:
Same Password + Salt B
       ↓
     Hash B
```

Salting also makes pre-computed password-guessing lists less useful.

---

## 19. Slow Password Hashing

Another defence is using deliberately **slow password-hashing functions**.

The idea is:

```text
Fast Hash
   ↓
Many guesses can be made quickly
```

Compared with:

```text
Slow Password Hash
   ↓
Each guess costs more
   ↓
Large-scale guessing becomes more expensive
```

I do not need the mathematical details yet.

The important concept is:

> Password hashing should make password guessing expensive.

# 29. My Final Understanding

Before this lesson, I mainly associated hashing with passwords and random-looking strings.

Now I understand the reason behind it.

A hash is basically a **digital fingerprint**.

I do not need to recover the original data from the fingerprint.

Instead, I can ask:

```text
Does this data still produce
the hash I expect?
```

If yes:

```text
Hash matches
    ↓
Data is consistent with the expected version
```

If no:

```text
Hash mismatch
    ↓
Something changed
    ↓
Investigate
```

For passwords, the same one-way property becomes useful because a system can verify a password without needing to store the original password.

The important distinction I now understand is:

```text
Encryption:
"I need to get the original information back."

Hashing:
"I need to verify the information without getting it back from the hash."
```

That is why hashing is not a worse version of encryption.

It is a completely different security tool.
