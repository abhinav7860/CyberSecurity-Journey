# Users and sudo

## What I learned

Today I learned about **Linux users, groups, root and sudo**.

Yesterday I learned about permissions — the rules for who can read, write or execute something. Today was about **who those rules actually apply to**.

Linux is built as a multi-user system, so different users can have different levels of access.

## 1. Normal Users vs Root

A normal Linux user is intentionally limited. They can work with their own files and run normal programs, but generally can't change important system settings or access other users' private files.

**Root** is the superuser/administrator and has almost complete control over the system. Root can read and modify files, change system settings, install or remove software, and create or delete users.

Because root has so much power, working as root all the time is dangerous. One wrong command can cause serious damage.

```text
Normal user → work normally
       ↓
Need extra privilege?
       ↓
Use sudo
       ↓
Back to normal user
```

This is the **least privilege** idea applied to Linux.

## 2. sudo

`sudo` means **superuser do**.

It allows a normal user to run a specific command with administrative/root privileges.

Example:

```bash
sudo apt update
```

Instead of logging in as root and staying there, I can use `sudo` only when I actually need extra privileges.

Some commands that may need sudo include:

```bash
sudo chown ...
sudo apt ...
```

The system may ask for the user's password before running the command.

I also learned that sudo actions can be logged, giving administrators an audit trail of privileged actions.

Not every user can use sudo. It is normally given only to trusted users.

## 3. Groups

A **group** is a collection of users who need similar access.

Instead of giving many users access to files one by one, they can be placed in a group and the files can have permissions for that group.

```text
project-team
     ├── user1
     ├── user2
     ├── user3
     └── user4
```

A user can belong to more than one group.

Groups make permission management easier, but they are also important for security. Being part of a powerful group can give a user more access than they should have.

The **sudo group** is a good example because membership can allow a user to perform actions as root.

## 4. Users and permissions together

Yesterday I learned:

```text
User | Group | Other
```

Today I understood who these actually represent.

Every file has:

- an owner
- a group
- permissions for the owner, group and others

Linux checks the user trying to access something and determines which permissions apply.

```text
Users
  ↓
Groups
  ↓
File ownership
  ↓
Permissions
  ↓
Access
```

If extra privileges are required:

```text
sudo → temporary root privileges
```

## 5. Why this matters in cybersecurity

Users, groups and sudo are important when securing or investigating a Linux system.

Things worth checking include:

- Who are the users on the system?
- Who can use sudo?
- Who belongs to powerful groups?
- Are there unexpected users?
- Are sensitive files owned by the correct user?
- Have permissions or ownership been changed?

On a compromised system, an attacker might create a new account, add themselves to a privileged group, or change ownership of files.

So checking users and groups can help identify suspicious activity.
