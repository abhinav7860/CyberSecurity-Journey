# Overview

Every application that communicates over a network must choose **how** its data will be delivered.

There are two primary transport protocols:

- **TCP** – Reliable, ordered, connection-oriented communication.
- **UDP** – Fast, lightweight, connectionless communication.

Although both operate on the same Internet and use IP addresses and ports, they behave very differently.

The choice between TCP and UDP affects:

- Speed
- Reliability
- Latency
- Performance
- User experience
- Security

---

# Two Ways to Send Data

An easy way to understand them is with a communication analogy.

## TCP – Like a Phone Call

Imagine making a phone call.

Before anyone starts talking:

```
Hello?
Hello, can you hear me?
Yes.
```

Only after both people confirm the connection does the conversation begin.

If something is missed:

```
Sorry, can you repeat that?
```

The conversation pauses until the missing information is received.

TCP behaves exactly this way.

It ensures:

- Every packet arrives.
- Packets arrive in the correct order.
- Missing packets are retransmitted.

---

## UDP – Like a Walkie-Talkie

UDP is similar to using a walkie-talkie.

```
Push button
Speak
Release
```

If the listener misses part of the message, it is simply lost.

There is:

- No confirmation
- No retransmission
- No ordering

The next message continues immediately.

---

# TCP vs UDP

| TCP | UDP |
|------|------|
| Connection-oriented | Connectionless |
| Reliable | Best effort |
| Ordered delivery | No ordering |
| Retransmits lost packets | No retransmission |
| Uses acknowledgements | No acknowledgements |
| Slower | Faster |
| Higher overhead | Low overhead |

---

# When is TCP Used?

TCP is used whenever data correctness is more important than speed.

Examples include:

- HTTP (Port 80)
- HTTPS (Port 443)
- SSH (Port 22)
- FTP
- SFTP
- SMTP
- IMAP
- POP3
- Database connections
- TLS encrypted communication

Example:

When opening a website, the browser establishes a TCP connection before downloading the page.

---

# When is UDP Used?

UDP is preferred when speed matters more than perfect delivery.

Examples include:

- DNS (Port 53)
- DHCP
- NTP (Port 123)
- Voice calls (VoIP)
- Video streaming
- Live broadcasts
- Online gaming

Example:

DNS only asks one question and expects one answer.

If the response is lost, the computer simply asks again.

---

# TCP Three-Way Handshake

Before any TCP communication begins, both devices establish a connection.

The process consists of three packets.

```
Client
   │
   │ SYN
   ▼
Server
   │
   │ SYN-ACK
   ▼
Client
   │
   │ ACK
   ▼
Connection Established
```

---

## Step 1 – SYN

The client sends:

```
SYN
```

Meaning:

> I want to start a connection.

---

## Step 2 – SYN-ACK

The server replies:

```
SYN-ACK
```

Meaning:

> I received your request and I'm ready.

---

## Step 3 – ACK

The client sends:

```
ACK
```

Meaning:

> Connection confirmed.

After this handshake, data transfer begins.

---

# Why TCP is Reliable

TCP provides several important features:

### Sequence Numbers

Every packet receives a sequence number.

This allows the receiver to arrange packets in the correct order.

---

### Acknowledgements (ACK)

The receiver confirms that each packet has arrived.

---

### Retransmission

If a packet is lost, the sender transmits it again.

---

### Flow Control

Prevents a fast sender from overwhelming a slower receiver.

---

### Congestion Control

Reduces transmission speed when the network becomes congested.

---

# Why UDP is Fast

UDP intentionally removes many TCP features.

There is:

- No handshake
- No ACK packets
- No retransmission
- No sequence numbers

This greatly reduces overhead.

If one packet is lost, communication continues without interruption.

This makes UDP ideal for:

- Gaming
- Voice calls
- Video conferencing
- Streaming

# Security Implications

The design of each protocol makes it vulnerable to different attacks.

---

## TCP Attacks

### SYN Flood

An attacker repeatedly sends SYN packets but never completes the handshake.

```
Attacker

SYN
SYN
SYN
SYN
SYN

(No ACK)
```

The server keeps waiting for responses until its connection table becomes full.

Result:

- Denial of Service (DoS)
- Legitimate users cannot connect

---

### Connection Hijacking

If an attacker predicts TCP sequence numbers and is on the communication path, they can inject malicious packets into an existing TCP session.

Modern systems use randomized sequence numbers to make this attack much harder.

---

# UDP Attacks

## UDP Flood

The attacker continuously sends UDP packets to random ports.

The operating system wastes CPU resources checking each packet.

---

## UDP Amplification Attack

The attacker sends a small UDP request using a spoofed source IP address.

```
Attacker
      │
Spoof Victim IP
      │
      ▼
DNS Server
      │
Large Response
      ▼
Victim
```

A tiny request can generate a much larger response.

Common amplification services:

- DNS
- NTP
- Memcached
