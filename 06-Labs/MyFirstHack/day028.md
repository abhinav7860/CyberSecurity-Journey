# NAT (Network Address Translation)
## Day 28 of 90 – How Networks Actually Work

**Date:** 03 August 2026

# Overview

Network Address Translation (NAT) is a networking technique that allows multiple devices on a private network to share a single public IPv4 address.

Although every device inside a home or office network has its own private IP address, the internet only sees the public IP address assigned to the router.

The router acts as a translator, keeping track of every connection and ensuring that responses are delivered back to the correct internal device.

Without NAT, the limited number of available IPv4 addresses would have been exhausted long ago.

---

# Why NAT Exists

IPv4 addresses are **32-bit** numbers.

This provides approximately:

```
2³² = 4,294,967,296
```

possible addresses (around **4.3 billion**).

When IPv4 was introduced in the early 1980s, this seemed like more than enough.

Today, however, there are tens of billions of internet-connected devices.

There simply are not enough unique public IPv4 addresses for every device.

NAT solved this problem by allowing many devices to share a single public address.

---

# Public vs Private IP Addresses

Every device inside a local network receives a **private IP address**.

Only the router receives a **public IP address** from the Internet Service Provider (ISP).

Example:

```
Laptop
192.168.1.10

Phone
192.168.1.20

TV
192.168.1.30

        │
        ▼

Home Router

Private IP : 192.168.1.1
Public IP  : 103.54.xx.xx

        │
        ▼

Internet
```

Although three different devices are connected, websites only see the router's public IP address.

---

# Private IPv4 Address Ranges

RFC1918 defines three private IPv4 address ranges.

These addresses are never routed directly on the public internet.

| Address Range | Number of Addresses |
|---------------|---------------------|
| `10.0.0.0 – 10.255.255.255` | ~16 million |
| `172.16.0.0 – 172.31.255.255` | ~1 million |
| `192.168.0.0 – 192.168.255.255` | ~65 thousand |

These ranges can be reused by anyone because they remain inside private networks.

For example:

- My home network can use `192.168.1.x`
- Your home network can also use `192.168.1.x`

Since neither network is directly exposed to the internet, there is no conflict.

---

# How NAT Works

Whenever a device communicates with the internet, the router performs address translation.

Example:

Laptop sends a request:

```
Source:
192.168.1.50:54321

Destination:
93.184.216.34:443
```

The router changes the source address before forwarding the packet.

Translated packet:

```
Source:
203.0.113.5:60001

Destination:
93.184.216.34:443
```

Here:

- `203.0.113.5` is the router's public IP.
- `60001` is a new port selected by the router.

When the server replies:

```
Destination:
203.0.113.5:60001
```

the router checks its NAT table and forwards the response to:

```
192.168.1.50:54321
```

The laptop never knows the translation occurred.

---

# NAT Translation Table

To manage multiple devices simultaneously, routers maintain a NAT translation table.

Example:

| Private Address | Public Address |
|-----------------|----------------|
| 192.168.1.50:54321 | 203.0.113.5:60001 |
| 192.168.1.20:50100 | 203.0.113.5:60002 |
| 192.168.1.15:61000 | 203.0.113.5:60003 |

Each connection receives a unique public port number.

This allows many devices to share a single public IP simultaneously.

---

# Port Address Translation (PAT)

The form of NAT used in almost every home router is called:

- PAT (Port Address Translation)
- NAPT (Network Address Port Translation)
- NAT Overload

Instead of assigning every device its own public IP address, PAT differentiates devices using different port numbers.

Example:

```
Laptop
192.168.1.10:53000

Phone
192.168.1.20:53001

TV
192.168.1.30:53002

↓

Router

Public IP

203.0.113.5

↓

Internet
```

The destination server only sees one public IP but different source ports.

---

# Static NAT (1-to-1 NAT)

Static NAT maps one private IP address to one dedicated public IP address.

Example:

```
192.168.1.50
↓

203.0.113.10
```

Unlike PAT, there is no sharing of addresses.

Static NAT is commonly used for:

- Enterprise servers
- Web servers
- Mail servers
- Datacenter infrastructure

# Security Implications of NAT

Although NAT was designed to conserve IPv4 addresses, it also provides some security benefits.

---

## Blocks Unsolicited Incoming Connections

External devices cannot directly initiate communication with internal devices because there is no existing translation entry.

Example:

Internet

↓

Attempts connection to:

```
192.168.1.50
```

The router has no NAT mapping for this request and therefore drops the packet.

This prevents many direct attacks against home devices.

---

## NAT is NOT a Firewall

A common misconception is:

> NAT = Security

This is incorrect.

NAT only performs address translation.

If malware running inside a network initiates an outbound connection:

```
Laptop

↓

Malware

↓

Command & Control Server
```

the router creates a valid NAT entry.

Replies from the attacker are then permitted.

NAT does **not** inspect the contents of traffic or decide whether the traffic is malicious.

That responsibility belongs to a firewall.

---

# Port Forwarding

Sometimes devices inside a private network need to accept external connections.

Examples:

- Hosting a website
- Running a Minecraft server
- SSH access
- Remote Desktop

Port forwarding manually tells the router where incoming traffic should go.

Example:

```
Internet

↓

Router

Port 80

↓

192.168.1.100
```

Incoming traffic on port 80 is forwarded directly to the internal web server.

---

# UPnP (Universal Plug and Play)

UPnP allows devices to automatically create port forwarding rules.

Advantages:

- No manual configuration

Disadvantages:

- Malware can also request port forwarding.
- Creates unnecessary exposure.
- Weakens network security.

For this reason, many security professionals recommend disabling UPnP unless absolutely necessary.

---

# NAT and Digital Forensics

From the internet's perspective, every device behind a router appears to originate from one public IP.

Example:

```
Laptop
↓

Phone
↓

TV

↓

Router

↓

203.0.113.5
```

Firewall logs only record:

```
203.0.113.5
```

Investigators must correlate NAT translation logs to identify which internal device generated specific traffic.

Without these logs, attribution becomes difficult.

---

# Carrier Grade NAT (CGNAT)

Many ISPs now perform an additional layer of NAT.

This is called:

**Carrier Grade NAT (CGNAT)**

Example:

```
Home Devices

↓

Home Router

↓

ISP NAT

↓

Internet
```

Instead of every household receiving a unique public IP address, many customers share one.

Benefits:

- Conserves IPv4 addresses

Disadvantages:

- Harder to host services
- More difficult forensic investigations
- Multiple customers share the same public IP

---

# NAT vs IPv6

IPv6 addresses are **128-bit**.

This provides:

```
340 undecillion
```

possible addresses.

Unlike IPv4, IPv6 has enough addresses for every internet-connected device to receive its own globally unique public address.

Because of this:

**IPv6 eliminates the need for NAT.**

Instead of hiding devices behind NAT, IPv6 relies on properly configured stateful firewalls for protection.

---

# IPv4 vs IPv6

| IPv4 | IPv6 |
|------|-------|
| 32-bit addresses | 128-bit addresses |
| ~4.3 billion addresses | 340 undecillion addresses |
| Requires NAT | NAT generally unnecessary |
| Private IP ranges | Global addressing model |
| Address shortage | Virtually unlimited addresses |

# Security Best Practices

- Do not rely on NAT as a security mechanism.
- Always enable a properly configured firewall alongside NAT.
- Disable UPnP unless it is required.
- Only configure port forwarding when necessary.
- Monitor NAT logs in enterprise environments for incident response.
- Restrict exposed services to the minimum required.
- Plan for IPv6 adoption while maintaining strong firewall policies.
