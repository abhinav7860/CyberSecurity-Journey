## 1. Putting the navigation commands together

The basic flow I practised was:

```text
pwd → check where I am
ls  → see what's there
cd  → move somewhere
```

Knowing the commands and actually being comfortable navigating are two different things. The practice today was mainly about making the commands feel more natural.

---

## 2. What fluent navigation looks like

Some things I focused on:

- Checking my location with `pwd`.
- Using `ls` after moving into a directory.
- Moving in small steps instead of typing huge paths every time.
- Using Tab completion instead of typing full names.
- Not getting stuck when I make a path mistake.
- Exploring a Linux system even if I haven't seen it before.

Errors such as:

```text
No such file or directory
```

are just feedback. I can check the path, correct it and continue.

---

## 3. Exploring an unfamiliar Linux system

I learned a simple way to approach an unknown Linux system.

First, I can look at the root directory:

```bash
ls /
```

Then I can focus on directories that are usually important:

```text
/home      → user directories
/etc       → configuration
/var/log   → logs
/tmp       → temporary files
```

When I reach a directory, I can use:

```bash
ls -la
```

to see the contents, including hidden files and more details.

If something looks interesting, I can move into it and continue checking.

The basic approach is:

```text
Start at the top
      ↓
Look around
      ↓
Go to important directories
      ↓
Check what is inside
      ↓
Drill down when something looks interesting
```

This is also useful for security investigations because Linux systems have a predictable structure.

---

## 4. Shortcuts I used

```bash
cd ~
```

Go back to my home directory.

```bash
cd -
```

Go back to the previous directory.

```bash
cd ..
```

Move one directory up.

```text
Tab
```

Complete file and directory names.

These make moving around much faster.
