# HTTP vs HTTPS

The lesson began by explaining the difference between HTTP and HTTPS.

## HTTP (HyperText Transfer Protocol)

HTTP transfers information between the browser and the web server **without encryption**.

This means:

- Data travels as plain text.
- Anyone intercepting the traffic can read it.
- Login credentials can be stolen.
- Cookies can be captured.
- Sensitive information can be exposed.

Example:

```
Browser
    ↓
HTTP Request
    ↓
Internet
    ↓
Web Server
```

Everything can be read while travelling across the network.

---

## HTTPS (HyperText Transfer Protocol Secure)

HTTPS is HTTP combined with **TLS encryption**.

Instead of sending readable data, HTTPS encrypts everything before transmission.

Example:

```
Browser
      ⇄
Encrypted TLS Tunnel
      ⇄
Web Server
```

Anyone intercepting the traffic only sees encrypted data.

---

# Why HTTPS Became Necessary

Years ago, many websites still used HTTP.

The lesson introduced **Firesheep**, a Firefox extension released in 2010.

It demonstrated how attackers on public Wi-Fi could easily steal:

- Facebook sessions
- Twitter sessions
- Amazon sessions

simply by capturing HTTP cookies.

This was one of the major reasons the internet rapidly migrated to HTTPS.

Today, around **95% of web traffic is encrypted**.

# What Does the Padlock Actually Mean?

One of the biggest lessons today was understanding what the padlock icon really guarantees.

When I see:

```
🔒 https://
```

it means three things have happened.

---

## 1. Encryption

The browser and the server negotiated an encrypted connection.

No one in the middle can read the transmitted data.

---

## 2. Certificate Verification

The website presented a digital certificate proving its identity.

---

## 3. Trusted Certificate Authority

The certificate has been signed by a trusted Certificate Authority (CA), which browsers already trust.

Examples include:

- GlobalSign
- DigiCert
- Sectigo
- Let's Encrypt
- Google Trust Services

---

# What the Padlock Does NOT Mean

This was probably today's biggest takeaway.

A padlock **does NOT mean:**

- The website is legitimate.
- The website is free of malware.
- The company is trustworthy.
- The website cannot be phishing.

A phishing website can have:

```
https://
```

and still steal usernames and passwords.

Encryption only protects the communication channel.

---

# Certificate Authorities (CA)

Certificate Authorities issue digital certificates.

Browsers trust hundreds of root Certificate Authorities.

Examples:

- GlobalSign
- DigiCert
- Sectigo
- Let's Encrypt
- Amazon Trust Services
- Google Trust Services

If a trusted CA signs a certificate, browsers automatically trust it.

---

# The Certificate Trust Chain

The lesson explained how browser trust works.

```
Website

↓

Certificate

↓

Certificate Authority

↓

Browser Trust Store
```

The browser checks whether:

- The certificate is valid.
- It hasn't expired.
- It matches the domain.
- The CA is trusted.

Only then does the browser display the padlock.

---

# DigiNotar Incident

One of the most interesting real-world examples was the **DigiNotar breach (2011).**

Attackers compromised the Dutch Certificate Authority DigiNotar.

They issued fake certificates for:

- Google
- Facebook
- Yahoo
- Mozilla
- CIA
- MI6

Browsers trusted these certificates because they were signed by a legitimate CA.

As a result, around **300,000 Iranian Gmail users** were monitored.

Eventually browsers removed DigiNotar from their trusted Certificate Authority list.

This demonstrated that browser trust depends heavily on Certificate Authorities.

# What Security Analysts Check

Instead of blindly trusting the padlock, analysts inspect several details.

## Domain Name

Always verify the actual domain.

Examples:

Correct:

```
paypal.com
```

Fake:

```
paypa1.com
```

```
paypal-login-security.com
```

```
paypal.verify-login.net
```

---

## Certificate Subject

Verify that the certificate was issued to the expected organization.

---

## Certificate Issuer

Check which Certificate Authority issued it.

---

## Validity Period

Modern certificates are intentionally short-lived.

Many now expire after only **90 days**.

# Task 2 — Comparing HTTP and HTTPS

For this task I visited:

```
http://neverssl.com
```

Unlike modern HTTPS websites, my browser clearly displayed:

```
Not Secure
```

There was **no padlock icon**.

When I inspected the connection, I noticed there was:

- No TLS handshake
- No certificate
- No encryption

I then compared it with a normal HTTPS website like BBC.

The HTTPS site negotiated:

```
TLS 1.3
```

whereas NeverSSL had no TLS information because it intentionally uses plain HTTP.

I also learned that NeverSSL exists primarily for **hotel, airport, and public Wi-Fi captive portals**, which sometimes require an HTTP connection before allowing internet access.

# HTTPS Protects the Channel

A very important concept from today's lesson:

HTTPS protects:

✔ Data in transit

It does **NOT** protect:

✘ Malicious websites

✘ Phishing pages

✘ Weak passwords

✘ Vulnerable web applications

✘ Malware

Encryption only secures the communication path between the browser and the server.
