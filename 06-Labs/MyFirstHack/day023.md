# Overview

Today's lesson introduced **Ports**, the second half of network addressing.

Yesterday I learned that an **IP address** identifies a device on the network. Today I learned that a **port number** identifies the application or service running on that device.

Without ports, a device would know that a packet belongs to it, but it would have no idea which application should receive it.

Together:

```
IP Address
        +
Port Number
        =
Complete Network Address
```

Every network conversation contains both.

---

# What is a Port?

A **port** is a logical communication endpoint used by applications.

Think of it as an apartment number inside a building.

- **IP Address** → Building
- **Port Number** → Apartment Number

Example:

```
Building
192.168.1.5

Apartment
443 (HTTPS)
```

The IP address delivers the packet to the correct device.

The port delivers the packet to the correct application.

---

# Port Range

Ports are **16-bit numbers**.

Possible range:

```
0 – 65535
```

This provides:

```
65,536 possible ports
```

Although thousands of ports exist, only a small number are commonly used.

---

# Source Port vs Destination Port

Every network connection contains **two port numbers**.

Example:

```
Source

192.168.1.10:53219
        │
        ▼
Destination

172.217.160.78:443
```

### Source Port

- Temporary
- Randomly chosen by the operating system
- Usually from the Dynamic Port range

Example:

```
53219
```

---

### Destination Port

Represents the service being accessed.

Example:

```
443
```

means

```
HTTPS
```

---

# Example

Opening a website:

```
Laptop

192.168.1.5:53219
        │
        ▼
Google

142.250.xxx.xxx:443
```

When Google replies:

```
Destination Port = 53219
```

The operating system knows the packet belongs to the browser and forwards it to Chrome or Firefox.

# Well-Known Ports

The Internet Assigned Numbers Authority (IANA) defines standard ports for common services.

These ports range from:

```
0 – 1023
```

Every networking professional should recognize the most common ones.

| Port | Service | Description |
|------|----------|-------------|
| 20/21 | FTP | File Transfer Protocol |
| 22 | SSH | Secure remote login |
| 23 | Telnet | Unencrypted remote login |
| 25 | SMTP | Sending email |
| 53 | DNS | Domain Name System |
| 80 | HTTP | Unencrypted web traffic |
| 110 | POP3 | Email retrieval |
| 143 | IMAP | Email retrieval |
| 443 | HTTPS | Secure web traffic |
| 587 | SMTP Submission | Email clients |
| 993 | IMAPS | Secure IMAP |
| 3306 | MySQL | Database |
| 3389 | RDP | Windows Remote Desktop |
| 5432 | PostgreSQL | Database |
| 5900 | VNC | Remote Desktop |

---

# Port Categories

Ports are divided into three categories.

| Range | Category | Purpose |
|--------|----------|----------|
| 0 – 1023 | Well-Known Ports | Standard Internet services |
| 1024 – 49151 | Registered Ports | Registered applications |
| 49152 – 65535 | Dynamic (Ephemeral) Ports | Temporary client connections |

---

# Dynamic Ports

When a browser opens a website, Windows or Linux automatically selects a random source port.

Example:

```
52381
54102
61534
```

These ports exist only for the duration of the connection.

---

# Open Ports

An **Open Port** means:

> An application is actively listening for incoming connections.

Examples:

```
22
SSH Server
```

```
80
Web Server
```

```
3306
MySQL Server
```

Open ports are necessary for services to function, but every open port increases the system's attack surface.

---

# Open Ports as Attack Surface

Every listening service represents a possible entry point.

If the service contains a vulnerability, attackers may exploit it.

The fewer open ports a system has, the smaller its attack surface.

---

# Types of Open Ports

## Localhost Only

```
127.0.0.1
```

Accessible only from the local machine.

Example:

A developer running a database locally.

Risk:

Very Low

---

## Private Network

```
192.168.x.x
```

Accessible only from devices on the local network.

Example:

- Printer
- NAS
- Router

Risk:

Depends on who has network access.

---

## Public Internet

Accessible from anywhere.

Examples:

- SSH
- Web Servers
- RDP

Risk:

Highest

These services are constantly scanned by attackers.

---

# Shodan

Shodan is a search engine for Internet-connected devices.

Instead of indexing websites, it indexes:

- Open Ports
- Services
- Banners
- Operating Systems
- Device Information

Attackers and defenders both use Shodan.

---

# Four Questions Every Open Port Should Answer

Every exposed service should answer:

1. Why is this port open?
2. Which service is running?
3. Is the service patched?
4. Who actually needs access?

If these questions cannot be answered, the port should probably be closed.

---

# Port Scanning

Port scanning is the process of checking which ports are open on a device.

It is one of the first reconnaissance techniques used during penetration testing.

---

# Nmap

The standard tool for port scanning is:

```
Nmap
(Network Mapper)
```

It can scan:

- One host
- Entire networks
- Internet ranges

Typical scan:

```
22 Open
80 Closed
443 Open
3306 Filtered
```

The results reveal which services are available.

---

# Why Attackers Scan Ports

Attackers scan systems to discover:

- Running services

- Potential vulnerabilities
- Attack opportunities
