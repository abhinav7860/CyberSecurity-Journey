# Overview

A firewall is one of the most fundamental security controls in networking. Its primary purpose is to **allow or block network traffic based on predefined security rules**.

Every packet that reaches a firewall is evaluated against a list of rules. If a rule allows the traffic, it passes through. If no rule permits it, the traffic is blocked.

Firewalls exist at multiple levels, including home routers, laptops, enterprise networks, cloud environments, and web applications. Although they all serve the same purpose, they differ significantly in the depth of inspection and security capabilities they provide.

---

# What is a Firewall?

A firewall is a network security control that monitors incoming and outgoing traffic and decides whether to allow or block it based on configured rules.

Every packet reaching a firewall is evaluated using attributes such as:

- Source IP Address
- Destination IP Address
- Source Port
- Destination Port
- Network Protocol (TCP, UDP, ICMP)

Based on the configured policy, the firewall either permits or denies the traffic.

---

# Types of Firewalls

Modern networks use several different types of firewalls depending on security requirements.

---

## 1. Packet Filtering Firewall

Packet filtering firewalls are the simplest type of firewall.

They inspect each packet independently without remembering previous communications.

They make decisions based on:

- Source IP
- Destination IP
- Port Number
- Protocol

### Advantages

- Fast
- Low resource usage
- Simple configuration

### Limitations

- No connection tracking
- Vulnerable to spoofed packets
- Cannot understand application traffic

Example:

Most ISP home routers use basic packet filtering.

---

## 2. Stateful Firewall

Stateful firewalls improve upon packet filtering by keeping track of active network sessions.

Instead of examining each packet individually, the firewall remembers previously established connections.

Example:

If your browser initiates an HTTPS connection to a website, the firewall records that session and automatically allows the returning packets.

Any unsolicited inbound traffic is blocked.

### Advantages

- Tracks active sessions
- Prevents spoofed responses
- Better security than packet filtering

Examples:

- Cisco ASA
- FortiGate
- Palo Alto (Classic Stateful Firewall)

---

## 3. Proxy Firewall (Application Gateway)

A proxy firewall acts as an intermediary between the client and the destination server.

Instead of forwarding packets directly, it:

1. Receives the client's request
2. Inspects the request
3. Creates a new connection to the destination
4. Returns the response

The destination server never communicates directly with the client.

### Advantages

- Hides internal systems
- Filters application traffic
- Better privacy

### Limitations

- Higher latency
- Additional resource consumption

Examples:

- Squid Proxy
- Zscaler
- Netskope

---

## 4. Next-Generation Firewall (NGFW)

Next-Generation Firewalls combine traditional stateful inspection with advanced security capabilities.

In addition to inspecting headers, they analyze the application data inside network packets.

Features include:

- Deep Packet Inspection (DPI)
- Application Awareness
- Intrusion Prevention
- Malware Detection
- URL Filtering
- SSL/TLS Inspection

Unlike traditional firewalls that only recognize ports, NGFWs can distinguish between different applications using the same port.

Example:

Both Microsoft 365 and a malicious website may use HTTPS (port 443), but an NGFW can identify the actual application and apply different security policies.

Examples:

- Palo Alto NGFW
- Fortinet FortiGate
- Check Point Firewall

# Firewall Rule Processing

Firewall rules are processed **from top to bottom**.

The **first matching rule** determines whether traffic is allowed or blocked.

Example rule set:

```text
Rule 1: ALLOW HTTPS (443)
Rule 2: ALLOW HTTP (80)
Rule 3: ALLOW SSH (22) from Office IP
Rule 4: DENY ALL
```

If an incoming packet matches Rule 1, it is immediately allowed and the remaining rules are ignored.

This is known as:

> **First Match Wins**

---

# Default Deny

Modern firewall configurations follow the principle of **Default Deny**.

Only explicitly permitted traffic is allowed.

Everything else is automatically blocked.

This follows the security principle:

> Allow only what is required.

---

# Whitelist vs Blacklist

## Whitelist (Allowlist)

Only approved traffic is allowed.

Everything else is denied.

Example:

- Allow HTTPS
- Allow SSH from Office
- Block everything else

Higher security but requires more administration.

---

## Blacklist (Blocklist)

Everything is allowed except explicitly blocked traffic.

Example:

- Block malicious IP addresses
- Allow everything else

Simpler to manage but significantly less secure.

Most enterprise environments use a **Whitelist + Default Deny** approach.

# Firewall Placement

Firewalls are deployed at multiple locations within a network.

---

## Perimeter Firewall

Located between the internal network and the internet.

Protects the organization from external threats.

---

## Internal Segmentation Firewall

Separates sensitive internal networks.

Example:

- Finance Network
- HR Network
- Database Servers
- Development Environment

Even if an attacker compromises one network segment, lateral movement is restricted.

---

## Host-Based Firewall

Runs directly on an endpoint.

Examples:

- Windows Defender Firewall
- iptables
- nftables
- pf

Provides protection even when devices leave the corporate network.

---

## Cloud Firewall

Cloud providers offer virtual firewalls for cloud resources.

Examples:

- AWS Security Groups
- Azure Network Security Groups
- Google Cloud Firewall Rules

They filter traffic before it reaches virtual machines.

---

## Web Application Firewall (WAF)

A WAF specifically protects web applications.

Instead of filtering packets at the network layer, it inspects HTTP and HTTPS traffic.

Common attacks blocked include:

- SQL Injection
- Cross-Site Scripting (XSS)
- Remote File Inclusion
- OWASP Top 10 attacks

Examples:

- Cloudflare WAF
- AWS WAF
- Imperva WAF

---

# What Firewalls Cannot Do

Firewalls are powerful but are not a complete security solution.

They cannot stop:

## Exploits inside Allowed Traffic

If HTTPS is allowed, attackers can exploit vulnerable web applications through legitimate HTTPS requests.

---

## Outbound Attacks

Once malware infects a system, it may establish outbound connections that are permitted by firewall rules.

---

## Encrypted Traffic

Unless SSL/TLS inspection is enabled, traditional firewalls cannot inspect encrypted HTTPS traffic.

---

## Social Engineering

Firewalls cannot stop:

- Phishing
- Fake Login Pages
- Email Scams
- Human Error

---

## Insider Threats

Users with legitimate access can still intentionally or accidentally compromise systems.

Firewalls cannot prevent misuse by authorized users.

---

# Defense in Depth

Modern organizations do not rely on a single firewall.

Instead, they combine multiple layers of security:

- Perimeter Firewall
- Internal Segmentation Firewall
- Host-Based Firewall
- Cloud Firewall
- Web Application Firewall
- Endpoint Detection & Response (EDR)
- Intrusion Detection & Prevention Systems (IDS/IPS)

This layered approach is known as **Defense in Depth**.

# Security Best Practices

- Follow the **Principle of Least Privilege**.
- Use a **Default Deny** policy.
- Review firewall rules regularly.
- Remove unused or outdated rules.
- Restrict administrative access.
- Segment internal networks.
- Enable logging and monitoring.
- Keep firewall firmware and software updated.
- Deploy a WAF to protect public-facing web applications.
- Combine firewalls with IDS/IPS and endpoint security solutions.
