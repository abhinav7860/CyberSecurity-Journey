# Day 17 -- The Cloud

## Understanding the Digital World

> **Key Idea:** The cloud is **someone else's computer**. Instead of
> buying physical servers, organizations rent computing resources from
> companies such as Amazon, Microsoft, or Google. Those companies
> maintain the hardware while customers deploy their own applications
> and data.

------------------------------------------------------------------------

# What is Cloud Computing?

Cloud computing is the delivery of computing services---servers,
storage, databases, networking, software, and analytics---over the
internet.

Instead of purchasing expensive hardware, businesses rent only the
resources they need and pay based on usage.

### Everyday Examples

-   Saving photos to iCloud or Google Photos
-   Watching Netflix
-   Using Google Docs or Microsoft 365
-   Hosting a website on AWS

### Advantages

-   Lower infrastructure cost
-   Fast deployment
-   Automatic scaling
-   Global availability
-   High reliability
-   Built-in backup options

# Core Cloud Services

## 1. Compute

Examples: - AWS EC2 - Azure Virtual Machines - Google Compute Engine

These are virtual computers running in a data centre.

**Think of it like:** Renting a powerful computer without buying one.

Typical uses: - Hosting websites - Running applications - Linux
servers - Game servers

------------------------------------------------------------------------

## 2. Storage

Examples: - Amazon S3 - Azure Blob Storage - Google Cloud Storage

Stores files such as: - Images - Videos - Documents - Backups -
Application files

### Why attackers like storage

If a storage bucket is accidentally made public, anyone on the internet
may be able to download sensitive files.

------------------------------------------------------------------------

## 3. Identity and Access Management (IAM)

IAM controls **who can do what**.

It decides: - Who can log in - Which resources they can access - What
actions they can perform

### Principle of Least Privilege

Every user or application should receive only the permissions required
to perform its task.

Giving unnecessary administrator rights increases risk.

------------------------------------------------------------------------

## 4. Networking

Cloud networking includes:

-   VPCs
-   Subnets
-   Firewalls
-   Security Groups
-   Routing Tables

These isolate systems and control which devices are allowed to
communicate.

------------------------------------------------------------------------

## 5. Databases

Examples: - Amazon RDS - DynamoDB - Azure Cosmos DB - Cloud SQL

Managed databases reduce administrative work because the cloud provider
handles updates, backups, and maintenance.

------------------------------------------------------------------------

## 6. Serverless Computing

Examples: - AWS Lambda - Azure Functions - Cloud Run

Instead of running a server 24/7, your code runs only when an event
occurs.

Benefits: - Lower cost - Automatic scaling - No server maintenance

# Shared Responsibility Model

This is the **most important concept** in cloud security.

## Cloud Provider Secures

-   Physical data centres
-   Hardware
-   Power and cooling
-   Hypervisors
-   Core cloud infrastructure

## Customer Secures

-   User accounts
-   IAM permissions
-   Applications
-   Databases
-   Encryption
-   Firewall rules
-   Uploaded data

**Remember:**

> The provider secures **the cloud**.
>
> You secure **what is inside your cloud account**.

------------------------------------------------------------------------

# Capital One Breach

The Capital One breach became one of the best-known cloud security case
studies because AWS itself was **not hacked**.

### Attack Flow

1.  A Web Application Firewall (WAF) was misconfigured.
2.  The attacker exploited SSRF (Server-Side Request Forgery).
3.  AWS Metadata Service returned temporary IAM credentials.
4.  The IAM role had excessive permissions.
5.  Hundreds of S3 buckets became accessible.
6.  Customer data was copied using:

``` bash
aws s3 sync
```

### Lessons Learned

-   Small configuration mistakes can combine into a major breach.
-   Least privilege limits damage.
-   Monitoring unusual activity is essential.
-   Cloud security is often about configuration rather than software
    vulnerabilities.

------------------------------------------------------------------------

# Cloud Security Audit Checklist

A security analyst should verify:

-   Storage buckets are not public.
-   IAM permissions follow least privilege.
-   Logging (CloudTrail, Activity Logs) is enabled.
-   Root accounts use MFA.
-   Sensitive data is encrypted.
-   Firewall rules expose only required ports.
-   Passwords and API keys are stored in a secrets manager.

------------------------------------------------------------------------

# Common Misconfigurations

-   Public storage buckets
-   Excessive IAM permissions
-   No MFA
-   Hardcoded API keys
-   Public databases
-   Disabled logging
-   Missing encryption
-   Overly permissive firewall rules

------------------------------------------------------------------------

# Best Practices

-   Enable Multi-Factor Authentication (MFA).
-   Regularly review IAM permissions.
-   Enable audit logs.
-   Encrypt sensitive data.
-   Rotate secrets and API keys.
-   Keep systems patched.
-   Continuously monitor for suspicious activity.
