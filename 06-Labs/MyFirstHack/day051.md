## What I learned

Today I learned about Linux **permissions**. I had already seen things like `-rwxr-xr--` when using `ls -l`, but I didn't really know what all those letters meant.

Permissions control **who can read, write, or execute a file**. This is an important part of Linux security because users should only have the access they actually need.

This connects with the **least privilege** idea I learned earlier in networking.

---

## 1. The three permissions

Linux mainly uses three permissions:

```text
r = read
w = write
x = execute
```

- **Read (`r`)** – view a file's contents or list a directory.
- **Write (`w`)** – modify a file or add/remove things in a directory.
- **Execute (`x`)** – run a file, or enter a directory using `cd`.

---

## 2. User, Group and Other

Permissions are applied to three categories:

```text
u = user
g = group
o = other
```

- **User** – the owner of the file
- **Group** – users belonging to the file's group
- **Other** – everyone else

So the basic model is:

```text
User | Group | Other
```

with read, write and execute permissions for each.

---

## 3. Reading `ls -l`

Example:

```text
-rwxr-xr--
```

I can break it down as:

```text
-    rwx    r-x    r--
│     │      │      │
│     │      │      └── Other
│     │      └───────── Group
│     └──────────────── User
└────────────────────── File type
```

The first character shows the type:

```text
- = regular file
d = directory
```

So `-rwxr-xr--` means:

```text
User  → rwx
Group → r-x
Other → r--
```

A `-` means that permission is not given.

---

## 4. `chmod`

`chmod` is used to **change permissions**.

Some examples:

```bash
chmod u+x file
chmod o-r file
chmod g+w file
```

The symbolic method is basically:

```text
u / g / o
+
-
r / w / x
```

For example, `chmod u+x file` adds execute permission for the owner.

---

## 5. Numeric Permissions

The numeric method uses:

```text
read    = 4
write   = 2
execute = 1
```

I add these values together.

```text
rwx = 4 + 2 + 1 = 7
r-x = 4 + 0 + 1 = 5
r-- = 4
```

So:

```bash
chmod 755 file
```

means:

```text
User  = 7 → rwx
Group = 5 → r-x
Other = 5 → r-x
```

Some common permissions I want to remember:

```text
755 → rwxr-xr-x
644 → rw-r--r--
600 → rw-------
```

- **755** – common for programs
- **644** – common for normal files
- **600** – owner-only access, useful for private files such as keys

---

## 6. `chown`

`chown` means **change owner**.

Example:

```bash
chown maya report.txt
```

This changes the owner of `report.txt`.

It can also be used to change the group. Changing ownership normally requires administrative privileges.

---

## 7. Why permissions matter in security

Permissions are an important part of Linux security.

A bad permission setting could make:

- sensitive files readable by everyone
- important files writable by users who shouldn't modify them
- files executable when they shouldn't be

For example, a configuration file containing a password being readable by everyone could expose sensitive information.

A script that is writable by everyone could also be modified by an attacker.

This is why checking permissions is useful during Linux security assessments and investigations.
