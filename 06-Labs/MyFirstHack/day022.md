# What is an IP Address?

An **IP (Internet Protocol) Address** is a unique identifier assigned to a device on a network.

Its primary purpose is to identify devices and ensure packets reach the correct destination.

Example IPv4 addresses:

```text
192.168.1.5
8.8.8.8
185.27.134.42
```

Every packet sent across a network contains:

- Source IP Address
- Destination IP Address

Without IP addresses, devices would not know where to send or receive data.

---

# IPv4

The most commonly used addressing system today is **IPv4 (Internet Protocol Version 4).**

Characteristics:

- 32-bit address
- Four decimal numbers
- Each number ranges from **0–255**
- Approximately **4.3 billion** unique addresses

Example:

```text
192.168.1.5
```

Each section is called an **octet** because it contains **8 bits**.

```
192 . 168 . 1 . 5
 8      8    8   8 bits

Total = 32 bits
```

---

# Network Part vs Host Part

Every IPv4 address consists of two logical parts.

| Part | Purpose |
|------|---------|
| **Network Portion** | Identifies the network the device belongs to. |
| **Host Portion** | Identifies the individual device on that network. |

### Postal Address Analogy

```
City
 ↓
London
```

represents the **network**.

```
Flat 4
22 Baker Street
```

represents the **host**.

Routers use the network portion to deliver packets to the correct network, while the host portion identifies the final device.

---

# Public vs Private IP Addresses

There are two categories of IPv4 addresses.

## Public IP Address

A **Public IP Address** is globally unique and reachable over the Internet.

Examples:

```text
8.8.8.8
```

Public IPs are assigned by Internet Service Providers (ISPs).

Examples include:

- Websites
- Cloud servers
- Home routers
- Public-facing services

Only one device on the Internet can have a specific public IP at a time.

---

## Private IP Address

Private IP addresses are used only within private networks.

These addresses are **not routable on the public Internet**.

The three reserved private ranges are:

| Range | Common Usage |
|--------|--------------|
| **10.0.0.0 – 10.255.255.255** | Large organizations and enterprise networks |
| **172.16.0.0 – 172.31.255.255** | Corporate networks and Docker environments |
| **192.168.0.0 – 192.168.255.255** | Home and small office networks |

Example:

```text
192.168.1.5
```

Millions of different homes can safely use this same address because private IPs never travel across the public Internet.

---

# Network Address Translation (NAT)

Since IPv4 provides only about **4.3 billion** addresses, the Internet needed a way for billions of additional devices to connect.

The solution is **Network Address Translation (NAT).**

## How NAT Works

Suppose your laptop has:

```
Private IP

192.168.1.5
```

Your router has:

```
Public IP

103.xxx.xxx.xxx
```

When your laptop sends a packet to Google:

1. Laptop sends the packet using its private IP.
2. Router replaces the source IP with its own public IP.
3. Google replies to the router.
4. Router translates the packet back to the laptop's private IP.

```
Laptop
192.168.1.5
        │
        ▼
Router (NAT)
Public IP
        │
        ▼
Internet
        │
        ▼
Google
```

Because of NAT, dozens of devices in a home can share a single public IP address.

---

# Why NAT is Important

Without NAT:

- Every device would require its own public IP.
- IPv4 addresses would have been exhausted long ago.

NAT allowed IPv4 to remain usable for decades despite the rapid growth of Internet-connected devices.

# IPv6

IPv6 was developed to solve IPv4 address exhaustion.

Characteristics:

- 128-bit address
- Eight hexadecimal groups
- Colon-separated

Example:

```text
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

IPv6 provides approximately:

```
340 undecillion addresses

3.4 × 10^38
```

This number is effectively unlimited for practical purposes.

---

# IPv6 Advantages

- Vastly larger address space
- Eliminates IPv4 exhaustion
- Modern protocol design
- Supports future Internet growth

Most modern devices support both IPv4 and IPv6 using **Dual Stack** networking.

If a website supports IPv6, the device uses IPv6.

Otherwise, it automatically falls back to IPv4.

---

# Why IPv6 Adoption is Slow

Despite being introduced in **1998**, IPv6 adoption remains gradual because:

- NAT still works effectively.
- Existing IPv4 infrastructure is widespread.
- Migrating enterprise networks requires significant effort.

As of **2026**, approximately **45%** of Internet traffic uses IPv6.

# What Your Public IP Reveals

Every server you connect to can see your **public IP address**.

This reveals useful information for security monitoring.

## Usually Reveals

- Country
- Region
- Approximate city
- Internet Service Provider (ISP)
- Whether you are using:
  - VPN
  - Proxy
  - Tor

---

## Does NOT Reveal

A public IP **does not directly reveal:**

- Your name
- Exact home address
- Personal identity
- What you are doing online

Only your ISP can associate a public IP with a customer, typically through legal processes.

---

# VPN and IP Addresses

When using a VPN:

Instead of seeing:

```
Your ISP IP
```

The destination website sees:

```
VPN Server IP
```

This hides your original public IP from the destination server.

However, the VPN provider can still see your traffic.

Using a VPN shifts trust from the destination website to the VPN provider.

---

# IP Addresses as Security Signals

Organizations monitor IP addresses to establish normal user behavior.

Typical login example:

```text
2026-04-12 14:23

London
BT Broadband
```

Later:

```text
03:47 AM

Tor Exit Node
Unknown Location
```

This unusual login may trigger a security alert.

---

# Impossible Travel Detection

Many organizations monitor login locations.

Example:

```
09:00 AM

India
```

Later:

```
09:45 AM

Germany
```

Since physically traveling between these locations in 45 minutes is impossible, the login is flagged as suspicious.

Examples of systems using this detection include:

- Google
- Microsoft 365
- Banks
- Enterprise authentication platforms
