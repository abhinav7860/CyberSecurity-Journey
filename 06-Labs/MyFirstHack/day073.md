## 2. The Breach Scenario

The scenario describes a mid-sized company that suffered a major breach in which customer data was stolen.

The attacker first researched the company online. They studied:

- The company website
- Employees on professional networks
- The organisation's email address format
- People working in the finance department

Using this information, the attacker created a convincing phishing email impersonating a known supplier.

The email contained a malicious attachment disguised as an invoice.

The attacker sent the email to several finance employees.

One employee opened the attachment.

The attachment exploited a vulnerability in outdated software on the employee's computer. This allowed the attacker's code to execute and provided an initial foothold.

After gaining access, the attacker:

- Installed a backdoor.
- Created a hidden scheduled task for persistence.
- Established communication with an attacker-controlled server.
- Explored the network.
- Stole credentials.
- Moved to other systems.
- Reached the server containing the customer database.
- Copied the customer database out of the network.

The breach was discovered later when the stolen data appeared for sale.

## 4. Mapping the Attack to the Kill Chain

The main analytical task was to assign every major attacker action to the correct Kill Chain stage.

| Kill Chain Stage | What Happened |
|---|---|
| Reconnaissance | Attacker researched the company, employees, email format, and finance department. |
| Weaponization | Attacker prepared a convincing phishing email with a malicious invoice attachment. |
| Delivery | Phishing email was sent to finance employees. |
| Exploitation | Victim opened the attachment and outdated software vulnerability was exploited. |
| Installation | Backdoor and hidden scheduled task were installed for persistent access. |
| Command & Control | Compromised machine connected to an attacker-controlled server. |
| Actions on Objectives | Customer database was copied out of the network. |

This converts a long narrative into a structured attack path.

## 5. Stage 1 — Reconnaissance

### What Happened?

The attacker started by researching the company.

They:

- Studied the company website.
- Found employees on professional networks.
- Identified the company's email format.
- Identified people working in finance.

This information helped the attacker understand the organisation and prepare a more convincing attack.

### Kill Chain Mapping

```text
RECONNAISSANCE

Company Website
      +
Employee Information
      +
Email Format
      +
Finance Department
      ↓
Understand the Target
```

This is the first stage because the attacker was gathering information before attempting the actual intrusion.

### Connection to My Learning

This directly connects to **Day 26 — Footprinting**.

The same kind of information that can be collected during legitimate security research can also be used by attackers when preparing an attack.

---

## 6. Stage 2 — Weaponization

### What Happened?

After researching the target, the attacker crafted a phishing email.

The email:

- Impersonated a known supplier.
- Was designed to look convincing.
- Contained a malicious attachment.
- Disguised the attachment as an invoice.

The attacker was preparing the actual weapon they intended to use against the target.

### Kill Chain Mapping

```text
Target Research
      ↓
Create Phishing Lure
      ↓
Prepare Malicious Attachment
      ↓
Weapon Ready
```

This belongs to **weaponization** because the attacker was preparing the malicious content before sending it.

---

## 7. Stage 3 — Delivery

### What Happened?

The attacker sent the phishing email to several finance employees.

The attack was delivered through email.

```text
Attacker
    ↓
Phishing Email
    ↓
Finance Employees
    ↓
Malicious Attachment
```

This is the **delivery** stage because the prepared weapon was being delivered to the intended targets.

### Defensive Opportunity

Possible defensive controls at this point include:

- Email security filtering
- Attachment inspection
- Phishing detection
- URL and content filtering
- Security awareness training

If the malicious email had been detected and blocked, the later stages could have been prevented through this path.

## 8. Stage 4 — Exploitation

### What Happened?

One employee opened the malicious attachment.

The attachment exploited a vulnerability in outdated software on the computer.

This allowed the attacker's code to execute and provided an initial foothold.

```text
Malicious Attachment
        ↓

        ↓
Outdated Software
        ↓
Vulnerability Exploited
        ↓
Code Executes
```

## 9. Stage 5 — Installation

### What Happened?

After gaining access, the attacker installed a backdoor and created a hidden scheduled task.

The scheduled task allowed the attacker to maintain access even if the computer restarted.

```text
Initial Foothold
      ↓
Backdoor
      ↓
Hidden Scheduled Task
      ↓
Persistent Access
```

This represents the **installation** stage of the Kill Chain.

### Connection to Previous Learning

This directly connects to **Day 62 — Cron Jobs**, where I learned how scheduled tasks can be used for persistence.

From a defensive perspective, unexpected scheduled tasks can be important indicators to investigate.

## 10. Stage 6 — Command and Control

### What Happened?

The compromised machine began quietly connecting to a server controlled by the attacker.

This gave the attacker a communication channel through which they could send commands and operate remotely.

```text
Compromised Machine
        ↓
Outbound Connection
        ↓
Attacker Server
        ↓
Remote Commands
        ↓
Compromised Machine
```

This represents **Command and Control (C2)**.

### Connection to Previous Learning

This connects directly to **Day 58 — Beaconing**.

Repeated or unusual outbound communication can provide a detection opportunity for a SOC analyst.

## 11. Stage 7 — Actions on Objectives

### What Happened?

Over the following weeks, the attacker:

- Explored the network.
- Stole credentials.
- Moved to other systems.
- Reached the customer database server.
- Copied the entire customer database outside the network.

The final objective was the theft of customer data.

```text
Compromise
    ↓
Explore
    ↓
Steal Credentials
    ↓
Move Through Network
    ↓
Reach Database
    ↓
Copy Customer Data
    ↓
Data Leaves Network
```

This is the **Actions on Objectives** stage because the attacker finally achieved the main goal of the intrusion.

### Connection to the CIA Triad

This represents a major **confidentiality** impact.

The attacker obtained sensitive customer information and removed it from the organisation's control.

This connects directly to **Day 66 — The CIA Triad**.

## 12. The ATT&CK Perspective

The Kill Chain gives the broad attack sequence, but Day 72 taught me that MITRE ATT&CK can provide more detail.

The scenario includes several behaviours that can be viewed through ATT&CK-style tactics.

| Activity | ATT&CK Perspective |
|---|---|
| Getting initial access through phishing | Initial Access |
| Running malicious code | Execution |
| Creating a scheduled task | Persistence |
| Avoiding detection through a hidden mechanism | Defence Evasion |
| Stealing credentials | Credential Access |
| Exploring the network | Discovery |
| Moving to other systems | Lateral Movement |
| Communicating with attacker infrastructure | Command and Control |
| Copying customer data out | Exfiltration |
| Theft of customer information | Impact on confidentiality / objective |

The scenario therefore shows why ATT&CK and the Kill Chain work well together.

The Kill Chain gives me the overall structure.

ATT&CK-style analysis gives me more detail about what the attacker was doing within that structure.

## 14. Finding Where the Chain Could Break

Mapping the attack is only the first part of the analysis.

The more important question is:

> **Where could the attack have been stopped?**

I went through the chain stage by stage.

### Reconnaissance

The company could reduce the amount of information available publicly.

```text
Less Public Information
        ↓
Less Information for Attacker
        ↓
Harder Targeted Reconnaissance
```

This does not necessarily eliminate reconnaissance, but it can reduce the information available to an attacker.

### Delivery

The phishing email could potentially have been detected before reaching employees.

Possible controls include:

- Email filtering
- Phishing detection
- Attachment inspection
- Security awareness training

```text
Malicious Email
      ↓
Email Security
      ↓
BLOCK
      ↓
Attack Stops
```

### Exploitation

This is one of the clearest defensive opportunities in the scenario.

If the vulnerability had been patched:

```text
Malicious Attachment
        ↓
Software Patched
        ↓
Exploit Fails
        ↓
No Initial Foothold
```

This connects directly to:

- **Day 60 — Package Managers**
- **Day 67 — Vulnerabilities**

### Installation

Monitoring persistence mechanisms could potentially detect the hidden scheduled task.

```text
New Scheduled Task
       ↓
Persistence Monitoring
       ↓
Unexpected Task Detected
       ↓
Investigation
```

This connects directly to **Day 62 — Cron Jobs**.

### Command and Control

Network monitoring could potentially identify:

- Unusual outbound connections
- Repeated communication
- Suspicious destinations
- Beacon-like behaviour

```text
Compromised Host
       ↓
Suspicious Outbound Traffic
       ↓
C2 Detection
       ↓
Investigation / Blocking
```

This connects directly to **Day 58 — Beaconing**.

### Actions on Objectives

Monitoring for unusual data transfers could potentially identify the database theft.

```text
Large Data Transfer
        ↓
Network Monitoring
        ↓
Possible Exfiltration
        ↓
Investigation / Response
```

## 16. The Most Important Lesson

The scenario made the central Kill Chain idea much clearer to me.

The attacker needed to successfully progress through the chain:

```text
Recon
  ↓
Weaponization
  ↓
Delivery
  ↓
Exploitation
  ↓
Installation
  ↓
C2
  ↓
Objective
```

The defender could potentially interrupt the attack at several different points.

This means security should not depend on a single control.

Instead, multiple layers can create multiple opportunities to detect or stop an attack.

This connects directly to **defence in depth**, which I studied earlier.
