# Network Attacks
## Day 33 of 90 · How Networks Actually Work

## 1. The Main Idea: Abuse of Trust

A lot of network attacks work because protocols trust information they receive without sufficiently verifying it.

For example:

ARP → Trusts whoever responds
DNS → Trusts the DNS response
Unencrypted traffic → Can be read by someone observing it

An attacker can abuse these assumptions to:

Intercept traffic
Redirect traffic
Read information
Modify communication
Overwhelm a service

The important defensive concept is:

Don't blindly trust network communication. Use encryption, verification and network segmentation.

## 2. Man-in-the-Middle (MitM)

A Man-in-the-Middle attack occurs when an attacker positions themselves between two communicating parties.

Normally:

Client  <----------------->  Server

During a MitM attack:

Client  <---------->  Attacker  <---------->  Server

The client and server may believe they are communicating directly.

The attacker can potentially:

Read traffic
Modify traffic
Capture credentials
Inject malicious content
Attempt to downgrade secure connections
Observe communication
Why MitM is dangerous

Once an attacker gets into the communication path, they can potentially manipulate the communication depending on the protocols and protections being used.

Defence

The main defence discussed was encryption and identity verification.

HTTPS uses TLS to:

Encrypt communication
Verify the server's identity using certificates

Therefore, even if an attacker gets between the client and server, properly protected HTTPS traffic should appear as encrypted data.

Important

Never ignore browser certificate warnings.

A certificate warning can indicate that the identity of the server cannot be properly verified.

## 3. ARP Poisoning

ARP stands for:

Address Resolution Protocol

ARP is used on a local network to map:

IP Address → MAC Address

For example:

192.168.1.1 → Router's MAC Address

A device can broadcast:

Who has 192.168.1.1?

The device owning that IP responds with its MAC address.

The Problem With ARP

ARP does not have built-in verification.

It essentially trusts the response.

An attacker on the same local network can abuse this by sending forged ARP responses.

For example:

Victim
   |
   | "Router is at this MAC"
   ↓
Attacker
   |
   ↓
Real Router

The victim may then send traffic through the attacker.

The attacker can forward the traffic to the real router so that the connection continues to work while the attacker remains in the middle.

This can create a Man-in-the-Middle position.

Detecting ARP Poisoning

In Wireshark, suspicious signs can include:

Unrequested ARP replies
Multiple MAC addresses claiming the same IP
A device's MAC address suddenly changing
Duplicate IP address warnings

Example:

IP Address: 192.168.1.1

MAC A → 192.168.1.1
MAC B → 192.168.1.1

This can indicate that something suspicious is happening.

Defence

Defences include:

Secure local networks
Network segmentation
Guest network isolation
Controlling who can connect to the network
Dynamic ARP Inspection on managed switches
Encryption such as HTTPS

ARP poisoning requires the attacker to be inside the local network, so protecting the local network is important.

## 4. DNS Spoofing

DNS translates domain names into IP addresses.

For example:

example.com
      ↓
IP Address

DNS spoofing abuses the trust placed in DNS responses.

An attacker can attempt to provide a false answer:

bank.example
      ↓
Attacker's IP

Instead of:

bank.example
      ↓
Real Bank IP

The victim may then connect to an attacker-controlled server.

Why DNS Spoofing Can Be Dangerous

The victim may believe they are visiting the correct website because the domain name they entered has not changed.

The underlying IP address has been manipulated.

This can potentially allow an attacker to create convincing copies of legitimate websites and attempt to steal information.

Detecting DNS Spoofing

In a packet capture, suspicious signs can include:

DNS responses from unexpected sources
A domain resolving to an unexpected IP
Multiple different answers to the same DNS query
DNS responses that don't match the expected infrastructure

Understanding normal DNS traffic makes these anomalies easier to notice.

## 5. DNS Spoofing Defences

Several technologies help defend against DNS manipulation.

DNSSEC

DNSSEC adds cryptographic signatures to DNS records.

It helps verify that DNS responses are authentic.

DNS over HTTPS (DoH)

DNS queries are sent through HTTPS.

DNS over TLS (DoT)

DNS queries are protected using TLS.

These technologies help protect DNS traffic from being read or modified in transit.

HTTPS as an Additional Defence

Even if DNS sends the user to the wrong server, HTTPS certificate validation provides another security layer.

An attacker-controlled server should not be able to provide a valid certificate for a legitimate domain.

Therefore:

DNS Protection
      +
HTTPS Certificate Validation
      +
Encryption

creates multiple layers of defence.

## 6. Denial of Service (DoS)

A Denial of Service attack attempts to overwhelm a target with traffic or requests so that legitimate users cannot access the service.

Normal:

Users → Server

During a DoS attack:

Huge amount of traffic
          ↓
       Server
          ↓
Resources exhausted

Possible result:

Legitimate users
       ↓
   Cannot connect

## 7. Distributed Denial of Service (DDoS)

A DDoS attack uses multiple systems to generate traffic against the target.

These systems can be part of a botnet.

Bot 1 ──┐
Bot 2 ──┤
Bot 3 ──┤
Bot 4 ──┤
        ↓
     Target

Because the traffic comes from many different sources, blocking it can be more difficult than blocking a single attacker.

## 8. SYN Flood

A SYN packet is used to begin a TCP connection.

Normal TCP handshake:

Client → SYN → Server
Client ← SYN-ACK ← Server
Client → ACK → Server

In a SYN flood, an attacker sends many SYN requests without completing the handshake.

Conceptually:

Attacker → SYN → Server
Attacker → SYN → Server
Attacker → SYN → Server
Attacker → SYN → Server
...

The server keeps resources available for incomplete connections.

This can exhaust the server's capacity.

Detecting a Flood

In a packet capture, you may notice:

Extremely high traffic volume
Large numbers of SYN packets
Many incomplete connections
Traffic coming from many sources in a DDoS
Connections that don't complete normally
Defence

Defences can include:

Traffic filtering
Rate limiting
DDoS protection services
Large-scale traffic absorption
Reverse proxies

Services such as Cloudflare can absorb and filter large amounts of malicious traffic before it reaches the origin server.

## 9. Packet Sniffing

Packet sniffing is the passive observation and capture of network traffic.

Wireshark itself is a packet analysis tool that can capture traffic.

The important difference is authorization.

Capturing your own traffic for learning or troubleshooting is appropriate.

Capturing other people's traffic without authorization can violate laws and policies.

Why Encryption Matters

On older or unencrypted networks, packet sniffing could expose:

Credentials
Messages
Data
Network activity

Modern encryption makes this much harder.

For example, with HTTPS:

Sniffer
   ↓
Encrypted traffic

The attacker may still observe metadata such as:

Source
Destination
Timing
Packet size

but should not be able to simply read the protected application contents.

## 10. Comparing the Attacks

Attack	Main Idea	Typical Detection
Man-in-the-Middle	Attacker gets between communicating parties	Unexpected communication path
ARP Poisoning	Forged ARP information redirects local traffic	Duplicate IP/MAC mappings
DNS Spoofing	False DNS response redirects traffic	Unexpected DNS responses/IPs
DoS	Overwhelm a service	Abnormally high traffic
DDoS	Distributed traffic flood	Large traffic volume from many sources
SYN Flood	Many incomplete TCP connections	Large number of SYNs without completion
Packet Sniffing	Passively capture traffic	Packet capture/monitoring

## 11. Common Defensive Themes

The attacks covered today have a common pattern:

Attacker abuses trust
        ↓
Traffic is intercepted,
redirected or overwhelmed
        ↓
Security impact

The major defensive technologies are:

Encryption

Protects traffic even if it is intercepted.

Examples:

HTTPS
TLS
VPNs
Verification

Makes it harder for attackers to impersonate legitimate systems.

Examples:

TLS certificates
DNSSEC
Network Segmentation

Limits what an attacker can access after entering a network.

Examples:

VLANs
Guest networks
Separate server networks
Monitoring

Helps identify abnormal traffic.

Examples:

Wireshark
Network monitoring
IDS/IPS
SIEM
