# Overview

A **Virtual Private Network (VPN)** creates an encrypted tunnel between a user's device and a remote VPN server.

Instead of connecting directly to websites through the ISP, all traffic first travels through the VPN server. The VPN server then forwards the requests to the destination on behalf of the user.

As a result:

- My ISP cannot see which websites I visit.
- Websites see the VPN server's IP address instead of my own.
- My traffic is encrypted while travelling across untrusted networks.

A VPN does **not** make me anonymous—it simply changes who can observe my network traffic.

---

# Why VPNs Exist

Without a VPN:

```
My Device
      │
      ▼
Home Router (NAT)
      │
      ▼
ISP
      │
      ▼
Internet
      │
      ▼
Website
```

My ISP can see:

- My public IP
- DNS requests
- Which domains I visit
- Connection metadata

---

With a VPN enabled:

```
My Device
      │
Encrypted Tunnel
      │
      ▼
VPN Server
      │
      ▼
Internet
      │
      ▼
Website
```

Now:

- ISP only sees encrypted traffic going to the VPN server.
- Websites see the VPN server's IP.
- DNS requests are handled by the VPN provider.

---

# How a VPN Works

A VPN requires three components:

- VPN Client
- VPN Server
- Encrypted Tunnel

The workflow is:

1. My computer establishes an encrypted tunnel.
2. All traffic is encrypted before leaving my device.
3. The VPN server decrypts the packets.
4. The VPN server forwards requests to websites.
5. Replies travel back through the encrypted tunnel.

This prevents anyone on the local network from inspecting my traffic.

---

# Encryption Used

Most modern VPNs use:

- AES-256 encryption
- WireGuard
- OpenVPN
- IKEv2/IPSec

Among these,

**WireGuard** is currently considered the preferred protocol because it:

- Faster
- Smaller codebase
- Easier to audit
- Modern cryptography

---

# What VPNs Actually Do

## 1. Encrypt Traffic

Anyone monitoring the local Wi-Fi network only sees encrypted packets.

This protects users on:

- Hotel Wi-Fi
- Airport Wi-Fi
- Coffee Shops
- Public Hotspots

---

## 2. Hide Browsing Activity From ISP

Without a VPN:

ISP sees:

```
example.com
google.com
github.com
```

With VPN:

ISP only sees:

```
Encrypted connection
↓

VPN Server
```

The ISP cannot determine which websites are being accessed.

---

## 3. Change Public IP Address

Because traffic exits through the VPN server,

Websites see:

```
VPN Server IP
```

instead of

```
My Home IP
```

This also allows changing the apparent geographic location.

---

## 4. Secure Remote Access

Businesses use VPNs so employees can securely access internal company resources remotely.

Examples:

- File Servers
- Internal Applications
- Corporate Databases
- Intranet

---

# What VPNs DO NOT Do

VPN advertisements often exaggerate their capabilities.

A VPN does **not**:

### Make Me Anonymous

The VPN provider can still see my traffic.

The trust simply shifts from:

```
ISP
```

to

```
VPN Provider
```

---

### Protect Against Malware

If malware downloads a malicious file,

the VPN simply encrypts and forwards that malware.

It does not stop infections.

---

### Hide My Identity

If I sign into:

- Google
- Microsoft
- Facebook

those services still know exactly who I am.

A VPN changes my IP—not my account identity.

---

### Replace HTTPS

HTTPS already encrypts communication between me and websites.

A VPN adds another encrypted layer but does not replace HTTPS.

---

### Stop Website Tracking

Websites can still identify me using:

- Cookies
- Browser Fingerprinting
- Logged-in Accounts
- Device Characteristics

VPNs do not prevent these tracking methods.

---

# When Should I Use a VPN?

A VPN is recommended when:

- Using public Wi-Fi
- Accessing corporate resources remotely
- Bypassing geographical restrictions
- Protecting browsing activity from ISP monitoring
- Traveling frequently

---

# When Should I NOT Depend on a VPN?

A VPN should never replace:

- Strong Passwords
- MFA
- Antivirus
- Software Updates
- Safe Browsing Habits

It is one security layer—not complete protection.

# What Did NOT Change?

Although my IP address changed,

the VPN did **not** change:

- My Google account identity
- Browser cookies
- Browser fingerprint
- Logged-in sessions
- Device information
- Operating System
- Browser version

Any website where I logged in would still recognize me despite the VPN.

During this practical exercise, I observed the exact changes introduced by a VPN connection.

Without the VPN:

- My ISP was visible.
- DNS queries were handled by Airtel.
- Websites identified my actual public IP.

After enabling Cloudflare WARP:

- My public IP changed.
- DNS requests were securely routed through Cloudflare.
- My ISP was hidden from visited websites.
- No DNS leak was detected.

This demonstrated that a VPN successfully changes network identity and encrypts traffic between my device and the VPN provider but does not provide complete anonymity or prevent website tracking.

# Security Best Practices

- Use VPNs when connected to public or untrusted Wi-Fi networks.
- Verify that DNS requests are routed through the VPN provider by performing DNS leak tests.
- Continue using HTTPS even when connected to a VPN.
- Enable Multi-Factor Authentication (MFA) for online accounts.
- Do not rely on VPNs for anonymity or malware protection.
- Avoid unknown free VPN applications; use trusted providers with transparent privacy policies.
