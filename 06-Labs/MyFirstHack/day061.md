## Overview

Day 61 was about moving from **using the command line** to **programming the command line**.

A Bash script is a text file containing commands that are executed automatically in sequence.

```text
Commands typed manually
        ↓
Commands written into a script
        ↓
Run the script
        ↓
Commands execute automatically
```

This is the beginning of automation.

Instead of repeating the same commands manually, I can put them into a script and run them whenever I need them.

For security work, this can be useful for gathering system information, collecting evidence, processing logs, performing routine checks, and monitoring systems.

---

# 1. What Makes a File a Script?

A Bash script mainly needs three things:

1. A **shebang**
2. Commands
3. Execute permission

```text
Shebang
   ↓
Commands
   ↓
Execute permission
   ↓
Runnable script
```

---

# 2. The Shebang

A Bash script normally starts with:

```bash
#!/bin/bash
```

This is called the **shebang**.

It tells the system that the script should be interpreted using Bash.

I had already seen this when investigating the suspicious script on Day 56.

---

# 3. Commands and Comments

Commands inside a script are executed from top to bottom.

```bash
echo "Hello"
date
ls
```

Comments can be added using `#`:

```bash
# sysinfo.sh - a simple system information script
```

The system ignores comments when running the script. Comments make scripts easier to understand later.

---

# 4. Execute Permission

A newly created script is initially just a text file. It needs execute permission before it can be run directly.

This connects directly to **Day 51 — Permissions**.

```bash
chmod +x sysinfo.sh
```

I can check the permissions with:

```bash
ls -l sysinfo.sh
```

The `x` in the permission string indicates execute permission.

```text
Text file
   ↓
chmod +x
   ↓
Execute permission
   ↓
Runnable script
```

---

# 5. Running a Script

A script in the current directory can be run with:

```bash
./sysinfo.sh
```

The `./` means to run the file from the current directory.

Without execute permission, the system can return:

```text
Permission denied
```

---

# 6. Variables

Variables allow a script to store and reuse values.

For example:

```bash
location=$(pwd)
```

This stores the current directory in a variable called `location`.

The value can then be retrieved using:

```bash
$location
```

For example:

```bash
echo "Current directory: $location"
```

```text
Store a value
     ↓
Variable
     ↓
Reuse the value
```

---

# 7. Conditions and Loops

Scripts can also make decisions and repeat actions.

An `if` statement can check whether something is true, while a loop can repeat an action over multiple items.

```text
Condition
   ↓
If true → perform an action
If false → handle differently
```

```text
Loop
   ↓
Repeat an action for multiple items
```

I don't need to master these today; the important point is that scripts can eventually respond to situations rather than only execute a fixed sequence.

# 9. My First Bash Script

For the practical task, I created:

```text
sysinfo.sh
```

The script gathers basic system information.

```bash
#!/bin/bash
# sysinfo.sh - a simple system information script

echo "=== System Information ==="

echo "Date:"
date

echo "Logged in as:"
whoami
location=$(pwd)
echo "Current directory: $location"
echo "=== End of report ==="
```

The commands used were:

| Command | Purpose |
|---|---|
| `echo` | Prints text |
| `date` | Displays the current date/time |
| `whoami` | Shows the current user |
| `pwd` | Shows the current working directory |

---

# 10. Creating the Script

I created the script using:

```bash
nano sysinfo.sh
```

Then I entered the Bash script and saved it from Nano using:

```text

Enter
Ctrl + X
```

# 11. Making the Script Executable

In my practical work I used:

```bash
chmod 700 sysyinfo.sh
```

This gave the owner read, write, and execute permissions.

I then ran:

```bash
./sysinfo.sh
```

The script executed successfully.

> Note: My terminal shows `chmod 700 sysyinfo.sh`, while the script I executed was `./sysinfo.sh`. The important result is that the script successfully ran.

       ↓

       ↓

Everything executes automatically

This becomes increasingly useful as tasks become larger or repetitive.
