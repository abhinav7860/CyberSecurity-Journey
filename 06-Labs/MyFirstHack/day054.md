# Searching the Filesystem

**Day 54 of 90 · Mastering the Command Line**
**Date Added: 1 September 2026**

## What I Learned

Today I learned how to **search for files in a Linux filesystem**. This is different from `grep`, which searches for text *inside* files.

- `grep` → searches **inside files**
- `find` → searches for **files/directories**
- `locate` → quickly searches filenames using an index

This is useful in cybersecurity when looking for suspicious files, recently modified files, unusual permissions, or files belonging to a particular user.

---

## `find`

`find` searches through the filesystem using different conditions.

### Find by name

```bash
find /home -name "report.txt"
```

Find files with a particular extension:

```bash
find /home -name "*.log"
```

The starting location matters:

```bash
find /
```

Searches the whole filesystem.

```bash
find .
```

Searches from the current directory.

---

## Useful `find` Options

### Find by type

```bash
find / -type f
```

`f` → regular files

```bash
find / -type d
```

`d` → directories

### Find recently modified files

```bash
find / -mtime -1
```

Finds files modified within the last day.

### Find files by owner

```bash
find / -user username
```

Useful for checking what files belong to a particular user.

### Find by size

```bash
find / -size +100M
```

Can help identify unexpectedly large files.

### Find by permissions

```bash
find / -perm -4000
```

Can be used to search for files with specific/risky permissions.

---

## Combining Conditions

Different `find` conditions can be combined.

```bash
find / -type f -mtime -1 -user www-data
```

This searches for regular files that were modified recently and are owned by `www-data`.

---

## `locate`

`locate` is another way to find files, mainly by name.

```bash
locate report.txt
```

It is usually much faster than `find` because it searches a **pre-built index** instead of checking the live filesystem every time.

### `find` vs `locate`

| `find` | `locate` |
|---|---|
| Searches the live filesystem | Searches an index |
| Can search by name, time, size, owner, permissions, etc. | Mainly searches by filename |
| Can be slower | Very fast |
| Better for investigations | Good for quick filename searches |
| Shows current filesystem state | Index can be outdated |

One limitation of `locate` is that its database may not contain very recently created files.

---

## Using `find` for Security

Some useful investigation questions:

**What changed recently?**

```bash
find / -mtime -1
```

**What's inside `/tmp`?**

```bash
find /tmp -type f
```

**What files belong to a particular user?**

```bash
find / -user username
```

**Are there files with risky permissions?**

```bash
find / -perm -4000
```

The important idea is that `find` lets me search based on **characteristics**, not just filenames.

---

## `grep + find`

The commands from Days 53 and 54 work together:

```text
grep → finds text inside files
find → finds the files themselves
```

During an investigation, I can first use `find` to locate files and then use `grep` to search their contents.

```text
Find recently modified configuration files
              ↓
        Examine the files
              ↓
       grep for suspicious text
```

This is becoming a basic investigation workflow for me.
