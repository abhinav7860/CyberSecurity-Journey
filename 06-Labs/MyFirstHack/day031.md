# What is Wireshark?

Wireshark is a **network protocol analyzer** (packet analyzer) that captures and displays network traffic in real time.

Instead of imagining how data travels across a network, Wireshark allows you to see every packet exchanged between devices.

It is widely used by:

- Network Engineers
- SOC Analysts
- Incident Responders
- Penetration Testers
- Malware Analysts
- Digital Forensic Investigators

---

# Why Wireshark is Important

Every action you perform online generates network traffic.

Examples include:

- Opening a website
- Sending an email
- Downloading a file
- Logging into a server
- Watching YouTube

Wireshark captures these communications and allows you to inspect them packet by packet.

Instead of reading theory about TCP handshakes or DNS lookups, you can actually watch them happen.

---

# How Wireshark Works

When Wireshark starts capturing traffic, it places the network interface into **promiscuous mode** (or capture mode depending on the interface).

Instead of modifying traffic, it simply copies packets as they pass through the network adapter.

```
Computer
      │
      ▼
Network Interface
      │
      ▼
Wireshark captures a copy
      │
      ▼
Packets continue normally
```

Wireshark is passive—it does **not** interfere with the communication.

# The Three Main Wireshark Panes

Every captured packet is displayed in three sections.

---

## 1. Packet List Pane

Located at the top.

Displays a summary of every captured packet.

Typical information includes:

- Packet Number
- Timestamp
- Source IP
- Destination IP
- Protocol
- Packet Length
- Brief Description

Example:

```
No.

Time

Source

Destination

Protocol

Length

Info
```

This pane provides an overview of all captured traffic.

---

## 2. Packet Details Pane

Located in the middle.

Shows detailed information about the selected packet.

The packet is broken down according to the OSI model.

Example:

```
Ethernet

↓

IPv4

↓

TCP

↓

HTTP
```

Expanding each protocol reveals additional fields.

Examples:

### Ethernet

- Source MAC
- Destination MAC

### IP

- Source IP
- Destination IP
- TTL

### TCP

- Source Port
- Destination Port
- Sequence Number
- ACK Number
- TCP Flags

### HTTP / DNS

Application-layer data.

This pane is where most packet analysis occurs.

---

## 3. Packet Bytes Pane

Located at the bottom.

Displays the raw packet data.

Shown in:

- Hexadecimal
- ASCII

Example:

```
45 00 00 3c ...

GET / HTTP/1.1
```

This is the actual packet transmitted across the network.

---

# Protocol Decoding

Packets are simply sequences of bytes.

Wireshark understands hundreds of protocols and automatically decodes them into human-readable information.

Instead of seeing:

```
45 00 00 3c ...
```

You see:

```
DNS Query

example.com
```

or

```
TCP SYN
```

This makes protocol analysis much easier.

# Display Filters

A normal web browsing session generates thousands of packets.

Display filters allow us to isolate only the packets we want to inspect.

---

## Filter by Protocol

Show only DNS traffic:

```
dns
```

Show only TCP:

```
tcp
```

Show only HTTP:

```
http
```

Show only ARP:

```
arp
```

---

## Filter by IP Address

Display traffic involving one IP address:

```
ip.addr == 8.8.8.8
```

Useful when investigating communication with a specific server.

---

## Filter by Port

Display HTTPS traffic:

```
tcp.port == 443
```

Display DNS traffic:

```
udp.port == 53
```

Ports learned in previous lessons become extremely useful here.

---

## Combining Filters

Display DNS packets involving a specific IP:

```
dns && ip.addr == 192.168.1.1
```

Logical operators:

```
&&

AND
```

```
||

OR
```

This allows very precise searches.

---

# Capture Filters vs Display Filters

There are two types of filters.

---

## Capture Filters

Applied **before** traffic is captured.

Only matching packets are recorded.

Used when:

- Long captures
- High-speed networks
- Reducing capture size

---

## Display Filters

Applied **after** packets are captured.

No packets are discarded.

Only the displayed packets change.

For learning and troubleshooting, display filters are generally preferred.

---

# Packet Coloring

Wireshark color-codes traffic.

Examples include:

- Green → HTTP
- Blue → DNS
- Black/Red → Errors or problematic packets

The colors help analysts quickly identify unusual network activity.

---

# Ethical Use of Wireshark

Wireshark is a powerful analysis tool.

It should only be used responsibly.

---

## Safe Usage

✔ Capture your own traffic.

✔ Analyze packets on networks you own or have permission to monitor.

---

## Do Not

❌ Capture other users' network traffic without authorization.

❌ Monitor traffic on corporate networks without approval.

❌ Use Wireshark to spy on others.

Doing so may violate:

- Company policies
- Privacy laws
- Computer misuse laws

---

# Encrypted Traffic

Most modern websites use HTTPS.

Wireshark can still display:

- Source IP
- Destination IP
- TCP Port
- TLS Handshake
- Packet Size
- Timing

However, the actual webpage content remains encrypted.

Think of it like this:

```
Envelope

Visible

✔
```

```
Letter inside

Encrypted

❌
```

Wireshark shows the envelope, not the message inside.
