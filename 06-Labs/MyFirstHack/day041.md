## What I Learned

IPv6 is the next generation of Internet addressing and the real solution to IPv4 address exhaustion.

IPv4 uses **32-bit addresses**, giving roughly **4.3 billion addresses**.

IPv6 uses **128-bit addresses**, giving roughly:

> **340 undecillion addresses**

This huge address space removes the scarcity problem that caused NAT to become common with IPv4.

# IPv4 vs IPv6

| Feature | IPv4 | IPv6 |
|---|---|---|
| Address size | 32-bit | 128-bit |
| Format | Decimal | Hexadecimal |
| Example | `192.168.1.1` | `2001:db8:85a3::8a2e:370:7334` |
| Address space | ~4.3 billion | ~340 undecillion |
| NAT | Common | Generally unnecessary |

# What an IPv6 Address Looks Like

An IPv4 address looks like:

```text
192.168.1.1
```

An IPv6 address looks like:

```text
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

An IPv6 address contains **8 groups of 4 hexadecimal digits**, separated by colons.

Hexadecimal uses:

```text
0-9
a-f
```

## IPv6 Shortening Rules

### 1. Remove Leading Zeros

For example:

```text
0db8 → db8
0000 → 0
0370 → 370
```

### 2. Replace One Run of Zeros With `::`

```text
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

can become:

```text
2001:db8:85a3::8a2e:370:7334
```

The `::` represents one or more groups of zeros.

Only **one `::`** can be used in an address because multiple `::` values would be ambiguous.

# IPv6 Address Types

## Loopback

The IPv6 equivalent of IPv4's `127.0.0.1` is:

```text
::1
```

It refers to the device itself.

## Link-Local

Link-local addresses start with:

```text
fe80
```

They are used for communication on the local network segment.

IPv6 devices automatically assign themselves a link-local address.

## Global

Global addresses are publicly routable IPv6 addresses.

Because IPv6 has such a large address space, devices can have their own globally routable addresses.

### Quick Reference

```text
::1       → Loopback
fe80::    → Link-local
Global    → Publicly routable
```

# What Changes When Addresses Are Unlimited?

IPv6 changes more than just the number of available addresses.

## NAT Becomes Unnecessary

IPv4 commonly uses NAT because public IPv4 addresses are limited.

IPv6 has enough addresses that devices can have their own addresses.

This means NAT is generally unnecessary.

However, NAT sometimes provided an accidental barrier against unsolicited inbound connections.

With IPv6:

> **The firewall has to explicitly provide that protection.**

A properly configured IPv6 firewall can block unwanted inbound traffic.

The security lesson is:

> **Security should be deliberate, not accidental.**

---

# SLAAC

IPv6 includes:

> **SLAAC — Stateless Address Autoconfiguration**

SLAAC allows devices to configure IPv6 addresses automatically without requiring a server to assign every address.

This is convenient, but it also means devices can appear on the network with automatically generated addresses.

This has implications for:

- Network visibility
- Tracking
- Device control

---

# IPv6 Privacy

Early IPv6 address generation could include information derived from a device's hardware/MAC address.

This created a privacy problem because the address could act as a recognisable identifier across different networks.

Privacy extensions were introduced to address this.

They can generate:

- Randomised addresses
- Rotating addresses

This makes tracking a device through one predictable IPv6 address more difficult.

# IPv6 Transition Security Problem

One of the biggest security concerns during the transition is securing IPv4 while forgetting about IPv6.

For example:

```text
                INTERNET
                    |
          ┌─────────┴─────────┐
          ↓                   ↓
        IPv4                IPv6
          ↓                   ↓
   Secured Firewall       Unmonitored
          ↓                   ↓
       Network             Network
```

If IPv6 is enabled but not monitored or filtered properly, an attacker may use the IPv6 path to bypass IPv4-only security controls.

Many devices have IPv6 enabled by default.

Therefore:

> **If IPv6 is running, it needs to be secured.**

An unsecured IPv6 stack next to a secured IPv4 stack can become an open door.

# IPv6 and the Security Mindset

## Defence Must Be Deliberate

NAT sometimes blocked inbound connections as a side effect.

Relying on that side effect for security is fragile.

IPv6 removes the need for NAT, so the firewall has to explicitly control inbound traffic.

This connects directly to the Zero Trust lesson:

> **Don't assume something is protected. Verify that the protection is actually there.**

## New Technology Brings New Attack Surface

IPv6 is a different protocol and has its own security considerations.

The general lesson is:

> **When adopting new technology, security has to keep pace with it.**

## The Unmonitored Path Is Dangerous

If IPv4 is monitored but IPv6 is ignored, IPv6 becomes a blind spot.

This connects with previous lessons:

- **Day 37 — SIEM:** monitoring only works when systems feed information into it.
- **Day 38 — Logs:** you can't investigate what you didn't log.
- **Day 40 — Zero Trust:** don't assume something is secure just because it is hidden.

The path that isn't being watched may be the path an attacker uses.

# Why Is the IPv6 Transition So Slow?

If IPv6 solves the IPv4 address problem, why isn't everything already IPv6?

## IPv4 and IPv6 Are Not Directly Compatible

An IPv4-only device cannot directly communicate with an IPv6-only device without transition or translation mechanisms.

Because of this, the internet cannot simply switch from IPv4 to IPv6 overnight.

Instead, both protocols operate in parallel.

This is commonly called:

> **Dual-stack**

## NAT Reduced the Pressure

NAT helped extend the life of IPv4.

Instead of every device needing a public IPv4 address, many devices could share one.

This reduced the immediate pressure to migrate to IPv6.

```text
IPv4 Address Exhaustion
        ↓
       NAT
        ↓
Problem Reduced
        ↓
IPv6 Migration Slowed
```

The workaround postponed the real fix.

# IPv4 vs IPv6 Security Mindset

IPv6 is not simply:

> **"IPv4 with bigger numbers."**

It changes how networks can handle addressing and introduces different security considerations.

### IPv4

```text
Limited Addresses
       ↓
NAT
       ↓
Shared Public Addresses
```

### IPv6

```text
Huge Address Space
       ↓
Direct Addressing
       ↓
Explicit Firewall Security
```

IPv6 makes deliberate security more important because devices can have globally routable addresses without needing NAT.

# Important Terms

## IPv6
The next generation of Internet Protocol addressing using 128-bit addresses.

## 128-bit
The address size used by IPv6.

## SLAAC
**Stateless Address Autoconfiguration**, allowing IPv6 devices to automatically configure addresses.

## Link-Local
IPv6 addresses beginning with `fe80`, used for communication on the local network segment.

## Loopback
The IPv6 loopback address:

```text
::1
```

## Global Address
A publicly routable IPv6 address.

## Dual-Stack
Running IPv4 and IPv6 at the same time.

## NAT
Network Address Translation, commonly used with IPv4 to allow multiple private devices to share public IPv4 addresses.

## Privacy Extensions
IPv6 mechanisms that can generate randomised/rotating addresses to reduce tracking.
