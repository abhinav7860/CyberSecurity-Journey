# Reading Files

**Day 53 of 90 – Mastering the Command Line**  
**Date Added: 1 September 2026**

## What I learned

Today I learned how to **read files properly in Linux**.

Until now I was mainly learning how to move around the filesystem and understand permissions. Now I started working with the actual contents of files.

This is especially important for cybersecurity because a lot of investigation is basically finding and reading the right files, especially logs, configuration files and system information.

---

## 1. `cat`

`cat` is useful for displaying the whole contents of a file.

```bash
cat filename
```

It works well for **small files**.

The problem is that if the file is huge, `cat` will dump everything onto the terminal and it becomes difficult to read.

So I should mainly use it when I know the file is small.

---

## 2. `less`

`less` lets me read a file one screen at a time.

```bash
less filename
```

I can move up and down through the file and search inside it.

To search:

```text
/word
```

To quit:

```text
q
```

This is much better for large files such as log files.

### Simple rule

```text
Small file → cat
Large file → less
```

---

## 3. `head`

`head` shows the beginning of a file.

```bash
head filename
```

By default it shows the first 10 lines.

I can also specify how many lines I want:

```bash
head -n 20 filename
```

This is useful when I just want to quickly check the beginning of a file instead of reading everything.

---

## 4. `tail`

`tail` shows the end of a file.

```bash
tail filename
```

It normally shows the last 10 lines.

This is especially useful with **logs**, because new log entries are usually added at the bottom.

So if I want to quickly see recent activity, `tail` is useful.

### `tail -f`

```bash
tail -f logfile
```

The `-f` option means **follow**.

It keeps showing new lines as they are added to the file, so I can watch a log in real time.

To stop it:

```text
Ctrl + C
```

---

## 5. `grep`

`grep` is one of the most useful commands I learned today.

Instead of showing the entire file, it searches for specific text and shows the matching lines.

Example:

```bash
grep "error" logfile
```

This shows lines containing `error`.

For authentication logs:

```bash
grep "failed" auth.log
```

This can quickly show failed login attempts.

### Useful grep options

```text
-i → ignore case
-n → show line numbers
-r → search recursively
-v → show lines that don't match
-c → count matches
```

Examples:

```bash
grep -i "error" logfile
grep -n "failed" auth.log
grep -r "password" /etc
grep -c "failed" auth.log
```

---

## 6. Choosing the right command

I learned that there isn't one command that is best for every situation.

```text
Whole small file → cat

Large file → less

Beginning → head

End/latest entries → tail

Watch a log live → tail -f

Find specific text → grep
```

This is useful in cybersecurity because investigation often means filtering a huge amount of information down to the part that actually matters.

For example:

```bash
tail auth.log
grep "failed" auth.log
grep "username" auth.log
less config.conf
grep -r "suspicious" /some/directory
```

The commands help me find the information, but I still need to **notice and understand what the results mean**.
