## 2. What is the CIA Triad?

The CIA Triad is one of the fundamental concepts of information security.

It has nothing to do with the intelligence agency. The three letters represent the three major security goals:

```text
                 CIA TRIAD
                     |
       +-------------+-------------+
       |             |             |
       v             v             v
 Confidentiality  Integrity   Availability
       |             |             |
       v             v             v
     SECRET       ACCURATE      ACCESSIBLE
```

Almost every security control exists to protect one or more of these properties.

Once I understood this, many of the things I had already learned started making more sense.

---

## 3. Confidentiality

### What does Confidentiality mean?

**Confidentiality means keeping information secret from people who should not have access to it.**

The main idea is that information should only be accessible to **authorised users**.

Examples of controls that protect confidentiality include:

- Passwords
- Authentication
- Encryption
- File permissions
- Access control
- Preventing network eavesdropping

### Simple Example

Imagine a company has a database containing customer information.

If an unauthorised person gets access to that database and reads the information, confidentiality has been violated.

```text
        CONFIDENTIALITY
               |
               v
       "Who can see this?"
               |
        +------+------+
        v             v
   Authorised     Unauthorised
      Access         Access
```

### Confidentiality Breach

Examples include:

- A leaked database
- Stolen passwords
- An intercepted message
- A private file being readable by the wrong user
- Unauthorised access to sensitive information

The main question I associate with confidentiality is:

> **"Who is allowed to see this information?"**

---

## 4. Integrity

### What does Integrity mean?

**Integrity means keeping information accurate and unaltered.**

Data should remain the way it is supposed to be unless an authorised person changes it.

Integrity protects information from unauthorised modification or tampering.

Examples include:

- Protecting files from unauthorised modification
- Verifying downloaded files
- Hashing
- Protecting messages from tampering
- Preventing unauthorised changes to records

### Simple Example

Suppose a banking transaction originally contains:

```text
Transaction Amount: ₹1,000
```

An attacker changes it to:

```text
Transaction Amount: ₹10,000
```

without authorisation.

That is an **integrity violation**.

```text
             INTEGRITY
                 |
                 v
        "Is the data correct?"
                 |
          +------+------+
          v             v
       Original       Tampered
         Data           Data
```

One important thing I understood is that incorrect data can sometimes be more dangerous than stolen data.

If data is stolen, we know there has been a breach.

But if data is silently changed, people might continue using incorrect information without knowing that it has been modified.

The main question I associate with integrity is:

> **"Is the information still correct and unchanged?"**

---

## 5. Availability

### What does Availability mean?

**Availability means keeping information and systems accessible to authorised users when they need them.**

Security is not only about preventing attackers from getting access. The system also needs to remain available for legitimate users.

Examples include:

- Keeping servers running
- Backups
- Disaster recovery
- Preventing Denial-of-Service attacks
- Protecting systems from ransomware
- Maintaining reliable services

### Simple Example

If an attacker launches a **Denial-of-Service (DoS)** attack against a website and legitimate users can no longer access it, availability has been affected.

Ransomware can also affect availability because users can be prevented from accessing their own files.

```text
             AVAILABILITY
                  |
                  v
       "Can authorised users
        access it when needed?"
                  |
           +------+------+
           v             v
        Available      Unavailable
```

The main question I associate with availability is:

> **"Can authorised users access the system or information when they need it?"**

## 6. The Three Properties Together

A simple way for me to remember the CIA Triad is:

```text
+-----------------------------------------+
|               CIA TRIAD                 |
+-----------------------------------------+
| C - Confidentiality -> Keep it SECRET   |
| I - Integrity       -> Keep it ACCURATE |
| A - Availability    -> Keep it ACCESSIBLE|
+-----------------------------------------+
```

So:

> **Secret + Accurate + Accessible = Secure Information**

The three properties together define the basic security goals for information and systems.

## 9. The CIA Triad Is Not About Maximising Everything

An important point from today's lesson is that the CIA Triad is not simply
about making all three properties as high as possible.

The three goals can sometimes create **trade-offs**.

For example, if I make a system extremely restricted, confidentiality may
improve, but legitimate users might not be able to access the system.

If I make everything freely accessible, availability may increase, but
confidentiality can be damaged.

```text
      Too Restricted
            |
            v
   Higher Confidentiality
   Lower Availability
            |
            v
      Hard to use

            ↓

      BALANCED SECURITY

            ↑

        Too Open
            |
            v
    Higher Availability
    Lower Confidentiality
            |
            v
       Less Secure
```

This shows why security requires **balance and judgement**.

A system that is so secure that nobody can use it has also failed at
security because availability is one of the security goals.

## 10. Security and Convenience

Security controls can also create friction for users.

For example, adding more authentication requirements can improve security,
but if the process becomes too difficult, users may start looking for
shortcuts.

Possible insecure workarounds could include:

- Writing passwords down
- Sharing accounts
- Avoiding security controls
- Creating insecure workarounds

This taught me that security controls should not simply be added without
thinking about how people will actually use the system.

The goal is not:

> **Maximum security at any cost.**

The goal is:

> **The right level of security for the situation.**

## 11. CIA Depends on the Situation

Different systems can give different importance to the three properties.

### Hospital

For life-support systems, **availability** can be extremely important.

The system must work when doctors and patients need it.

### Sensitive Information

For highly confidential information, **confidentiality** may be the most
important property.

Keeping the information secret can be more important than making it widely
accessible.

### Banking

For financial transactions, **integrity** is extremely important.

Transaction records and financial values need to remain accurate.

| Environment | Important Property | Why |
|---|---|---|
| Hospital life-support system | Availability | The system must remain operational |
| Sensitive secrets | Confidentiality | Information must remain private |
| Banking transactions | Integrity | Financial information must remain accurate |

This showed me that there is no universal answer such as "one part of CIA is
always the most important."

It depends on the **system, purpose, and consequences of failure**.

## 12. Why Context Matters

Security decisions cannot always be made using a fixed recipe.

A security professional needs to ask:

```text
What system am I protecting?
          |
          v
What information does it contain?
          |
          v
What could go wrong?
          |
          v
Which CIA property is affected?
          |
          v
What would the impact be?
          |
          v
What level of protection is appropriate?
```

This is where security becomes more about **judgement** than simply
memorising commands.

## 14. CIA as a Professional Security Language

Another important thing I learned is that the CIA Triad gives security
professionals a more precise way of describing incidents.

Instead of saying:

> "This attack is dangerous."

I can explain its actual security impact.

For example:

> "This is a confidentiality breach because sensitive customer data was exposed."

Or:

> "This ransomware incident primarily affects availability because users can no longer access their files."

Or:

> "The attacker modified the database records, which is an integrity violation."

This way of describing incidents is much more precise.

It also gives me a better way to communicate security issues during
interviews and professional work.
