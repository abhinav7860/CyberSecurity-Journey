# Overview

Day 20 marks the end of **Phase 1.1** of the course. Instead of learning a new cybersecurity concept, this milestone focuses on applying everything learned over the past twenty days to build a **personal threat model**.

A threat model is a structured document that identifies what you want to protect, who might attack it, how they might attack, and what defenses should be prioritized.

Unlike a generic security checklist, a threat model is personalized. It helps prioritize security measures based on your own assets, risks, and likely attackers.

The final output is a professional document that can be included in a cybersecurity portfolio and discussed during interviews.

---

# What is a Threat Model?

A threat model is a structured security assessment used to identify risks and determine appropriate defenses.

Every threat model answers four fundamental questions:

1. **What am I trying to protect?**
2. **Who would want to attack it, and why?**
3. **How would they attack it?**
4. **What can I do to reduce the risk?**

These four questions form the foundation of professional threat modeling frameworks such as:

- STRIDE
- PASTA
- Attack Trees
- LINDDUN

Although each framework has its own methodology, they all aim to answer these same questions.

---

# The Four Core Questions

| Question | Focus |
|----------|-------|
| **What am I protecting?** | Identify valuable assets. |
| **Who are the attackers?** | Determine realistic threat actors. |
| **How would they attack?** | Create possible attack scenarios. |
| **How can I defend?** | Prioritize security controls and improvements. |

---

# Why Threat Modeling Matters

Many cybersecurity recommendations are presented as universal checklists.

Common examples include:

- Use Multi-Factor Authentication (MFA)
- Install antivirus software
- Use a password manager
- Keep software updated

While these practices are valuable, they assume every user has the same level of risk.

Threat modeling takes a different approach by focusing on the individual.

Instead of asking:

> "What security advice exists?"

It asks:

> "Which security measures are most important for my specific situation?"

This allows security efforts to be prioritized based on realistic risks rather than generic recommendations.

---

# Checklist vs Threat Model

| Security Checklist | Threat Model |
|--------------------|--------------|
| Generic recommendations | Personalized recommendations |
| Same advice for everyone | Tailored to individual risks |
| Focuses on best practices | Focuses on likely threats |
| No prioritization | Risk-based prioritization |
| Broad security guidance | Practical security strategy |

# What i Will Build

By the end of this milestone, i will have a single professional document containing five sections.

## 1. Asset Inventory

List everything you want to protect.

Examples:

- Email accounts
- Password manager
- Laptop
- Mobile phone
- Banking accounts
- Cloud storage
- Social media accounts
- Personal documents

Rank assets by importance.

---

## 2. Threat Actor Profile

Identify who is most likely to target you.

Possible threat actors include:

- Cybercriminals
- Phishing attackers
- Identity thieves
- Scammers
- Malware operators
- Insider threats

For each threat actor, identify:

- Motivation
- Target
- Potential impact

---

## 3. Attack Scenarios

Create three realistic attack scenarios for your most valuable assets.

Each scenario should follow the **Cyber Kill Chain**.

Example:

```
Reconnaissance
      ↓
Weaponization
      ↓
Delivery
      ↓
Exploitation
      ↓
Installation
      ↓
Command & Control
      ↓
Actions on Objectives
```

This helps visualize how an attack could progress from beginning to end.

---

## 4. Defense Map

For each attack scenario, document:

### Existing Protections

Examples:

- MFA enabled
- Strong passwords
- Password manager
- Device encryption
- Antivirus
- Software updates

### Security Gaps

Examples:

- Weak recovery methods
- Missing backups
- Publicly available personal information
- Poor account monitoring

---

## 5. Priority Matrix & 90-Day Plan

Evaluate each risk based on:

- Likelihood
- Impact

A simple priority matrix helps determine which risks should be addressed first.

Example:

| Likelihood | Impact | Priority |
|------------|--------|----------|
| High | High | Immediate |
| High | Medium | High |
| Medium | Medium | Medium |
| Low | High | Medium |
| Low | Low | Low |

Finally, define the **top three security improvements** to complete within the next **90 days**.
