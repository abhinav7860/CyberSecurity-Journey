## 1. Introduction

Today, I learned about **defence in depth**, a core principle of defensive security architecture.

The principle is simple: never rely on a single security measure. Use multiple layers so that if one fails, others can still protect the system. No single defence is perfect. A firewall can be misconfigured, a password can be stolen, an employee can be fooled, a patch can be missed, or a security tool can have a blind spot.

The goal is not to build one perfect, impenetrable wall. It is to build several imperfect layers whose weaknesses do not all overlap.

A useful question for defenders is:

> If this layer fails, what catches the attacker next?

## 2. Picturing Defence in Depth

### The castle metaphor

A well-defended castle used multiple barriers: a moat, outer wall, inner wall, keep, gates, and guards. Crossing one barrier did not mean the attacker had won; other defences remained. Digital security follows the same principle: getting past one defence should bring an attacker up against another.

The lesson distinguishes defence in depth from over-relying on the older **castle-and-moat** approach. Zero trust (Day 40) challenges excessive trust in the perimeter, but still supports layering and verification at every layer.

### The onion metaphor

An onion has layers surrounding its centre. In security, valuable data sits at the centre, with multiple protective layers around it. An attacker must get through successive layers to reach the data.

### The Swiss cheese model

The Swiss cheese model explains why imperfect layers can work together. Each slice represents a defence and contains gaps because no individual control is perfect. When several slices are stacked, their gaps are less likely to line up.

```text
Attack
  |
  v
[Layer 1: gaps] ---> [Layer 2: different gaps] ---> [Layer 3: different gaps]
                              |
                              v
                 Another layer may stop the attack
```

For an attack to pass through the whole stack, gaps in multiple layers would need to align. This is why a combination of imperfect defences can be stronger than relying on one defence alone.

## 3. The Kinds of Defensive Layers

Defence in depth works across several dimensions.

### A. Layers by location: outside in

| Layer | Examples | Purpose |
|---|---|---|
| Physical security | Locks, badges, guards | Protect physical hardware and facilities |
| Network security | Firewalls, network segmentation | Control network traffic and limit movement |
| Host security | System hardening | Protect individual systems |
| Application security | Secure software practices | Reduce and defend against application vulnerabilities |
| Data security | Encryption | Protect data, including when other layers are breached |

This resembles the onion model. If the network is breached, host security may still protect individual machines. If a host is compromised, encryption may still help protect data from being read.

### B. Layers by function: prevention, detection, and response

| Function | Goal | Examples |
|---|---|---|
| Prevention | Stop attacks before they succeed | Firewalls, patching, access control |
| Detection | Notice attacks that get past prevention | Monitoring, logs, intrusion detection |
| Response | Act on detected attacks | Incident response and containment |

These functions are complementary. Prevention will sometimes fail, so detection and response are necessary to identify and limit damage. A defence focused only on prevention may leave an attacker operating unseen if the attacker gets inside.

### C. Layers by people, process, and technology

- **People:** Training and awareness that help employees recognise threats such as phishing.
- **Process:** Policies and procedures that guide people to work securely.
- **Technology:** Security tools and technical controls.

Security is not only a technical problem. A useful tool can fail to protect an organisation if people are not trained or the right processes are not followed. Strong defence in depth combines all three dimensions: location, function, and people/process/technology.

## 4. Defence in Depth and the Cyber Kill Chain

The Cyber Kill Chain (Day 71) describes stages an attack moves through. Defence in depth puts protective and detection layers at multiple points in that attack lifecycle.

| Kill Chain stage | Example defensive layer |
|---|---|
| Delivery | Email filtering |
| Exploitation | Patching vulnerable software |
| Installation | Detecting suspicious persistence |
| Command and Control | Detecting suspicious beaconing or communications |
| Actions on Objectives | Monitoring for data exfiltration |

The attacker must progress through the stages to achieve the objective, while defenders have opportunities to disrupt the attack at different points.

- The **Cyber Kill Chain** helps identify where an attack may be interrupted.
- **Defence in depth** encourages defenders to place multiple layers across those stages.
- If one layer misses the attack, another may detect or stop it later.

The Day 73 breach scenario illustrated how an attack can progress when defensive gaps exist across multiple stages. Defence in depth reduces the chance that every stage will lack an effective control.

## 5. Assume Breach and Zero Trust

Because early prevention can fail, defenders should not assume that the perimeter will always hold. The lesson describes an **assume-breach** mindset: plan for the possibility that an attacker may already be inside and ensure there are deeper layers of monitoring, detection, and response.

This connects to **zero trust** (Day 40), which rejects automatic trust based only on network location. Systems and users should be verified, and activity should be monitored at multiple layers.

Together, defence in depth, the Cyber Kill Chain, and assume-breach thinking support a realistic defensive posture: build multiple layers across the attack lifecycle, including inside the network, rather than depending only on the outer perimeter.

## 7. Quick Revision

- **Defence in depth:** Use multiple defensive layers so one failure is not catastrophic.
- **Castle metaphor:** An attacker who passes one barrier still faces others.
- **Onion metaphor:** Multiple layers surround valuable data.
- **Swiss cheese model:** Imperfect layers work together because their gaps do not always align.
- **Location-based layers:** Physical, network, host, application, and data security.
- **Functional layers:** Prevention, detection, and response.
- **People, process, technology:** Effective security requires all three.
- **Kill Chain connection:** Place defences at multiple stages of an attack.
- **Assume breach:** Plan for attackers getting past the perimeter and maintain deeper detection and response.
- **Zero trust:** Do not rely on perimeter location alone as proof of trust.

## 8. What I Learned

Today, I learned that security should not depend on a single control. Even a useful defence can fail because of misconfiguration, missed patches, stolen credentials, human error, or tool limitations.

I understood defence in depth through the castle, onion, and Swiss cheese models. I also learned that layers can be organised by location, by function, and across people, process, and technology.

The most important connection for me is between defence in depth and the Cyber Kill Chain.
