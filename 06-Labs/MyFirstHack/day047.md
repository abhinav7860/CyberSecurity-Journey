# Ways to run Linux

## 1. WSL

**Windows Subsystem for Linux (WSL)** is the easiest option if I'm using Windows.

It lets me run a real Linux environment inside Windows without having to install a completely separate operating system.

For this course, WSL is a good option because the main thing I need is the Linux command line.

## 2. Virtual Machines

A virtual machine is basically another computer running inside my actual computer.

Tools such as VirtualBox and UTM can be used to create a VM and install Linux inside it.

The Linux system is isolated from the main system and can also provide the full Linux desktop experience.

The downside is that VMs use more system resources and take a little more work to set up.

## 3. Cloud / Browser Linux

Another option is using a Linux server in the cloud or a browser-based Linux terminal.

This can be useful when local installation isn't possible.

The downside is that having Linux locally is generally more convenient for this phase because I can practise whenever I want.

## 4. Dual Boot / Full Installation

Linux can also be installed directly on a computer.

This can be done alongside another operating system using dual boot, or Linux can completely replace the existing operating system.

This gives good performance, but it is more complicated and carries more risk if something goes wrong.

For learning the command line, I don't really need to go this far.

# Ubuntu

The Linux distribution used for this phase is **Ubuntu**.

Ubuntu is a popular Linux distribution and is a good choice for learning because:

- It is beginner friendly
- It is widely used
- There is a huge amount of community support
- It is free
- It is regularly maintained
- What I learn on Ubuntu can transfer to other Linux distributions

The lesson recommends using a current **LTS (Long-Term Support)** version.

# Why not start with Kali?

Since this is a cybersecurity course, I might expect Kali Linux to be the obvious choice.

But the reason for starting with Ubuntu makes sense.

Kali is mainly built as a security testing distribution with lots of security tools already installed.

If I am still learning basic Linux, I don't need hundreds of security tools yet.

It's better to learn the fundamentals first.

The commands I learn on Ubuntu will also work across other Linux distributions such as:

```text
Ubuntu
Kali
Debian
```

So the important part is learning Linux itself, not starting with a specialised security distribution.

# Understanding the Linux prompt

When Linux starts, I get a command-line prompt waiting for me to type something.

A typical prompt can look something like:

```text
username@computer:~$
```

There are a few useful things here.

The username tells me which user I am.

The computer name identifies the system.

The `~` represents my home directory.

The `$` means the shell is ready for a command.

So the basic idea is:

```text
username@computer:~$
                    ^
                    ready for command
```

# Linux username and password

When setting up Ubuntu, I need to create a Linux username and password.

This is separate from my normal Windows or Mac login.

One thing that can be confusing the first time is entering the password.

When typing a Linux password in the terminal:

```text
Nothing appears
```

There are no dots, asterisks, or anything else showing the characters.

That is normal.

I just type the password and press Enter.

# First commands

The first commands aren't supposed to be complicated.

The point is just to make sure the environment is working and start getting comfortable with the terminal.

The basic idea is:

```text
Type command
     |
     v
Press Enter
     |
     v
Linux executes it
     |
     v
Result appears
```

This is the same command-line model that I will keep using throughout the Linux phase.

# Setup problems

One thing I liked about this lesson is that it didn't pretend setup is always perfect.

Linux installation can sometimes be annoying.

There can be:

- Settings that need to be enabled
- Downloads
- Restarts
- Configuration problems
- Error messages

That doesn't mean Linux itself is too difficult.

The setup is often harder than the actual commands.

Once the environment is working, the learning becomes much easier.

# Getting stuck is part of learning

A useful thing I learned today is that searching for solutions is part of working with Linux.

If I get an error, I should:

```text
Read the error
     |
     v
Copy the important part
     |
     v
Search for the exact error
     |
     v
Check the solution
     |
     v
Try it
```

Linux and WSL are used by so many people that most common problems already have solutions online.

So getting stuck doesn't mean I don't understand Linux.

Learning how to get unstuck is also part of becoming comfortable with it.
