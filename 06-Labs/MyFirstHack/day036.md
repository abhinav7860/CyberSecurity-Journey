## The problem with doing it by hand

Yesterday I investigated a traffic capture manually by orienting myself, filtering traffic, following conversations, and identifying what I found.

That works, but it doesn't scale.

A real network can have millions or even billions of packets, and no human can watch all of that traffic continuously and find one malicious connection among normal traffic.

This is where **IDS** and **IPS** come in.

An **Intrusion Detection System (IDS)** watches network traffic and alerts when it finds something suspicious.

An **Intrusion Prevention System (IPS)** does the same thing, but it can also block malicious traffic in real time.

The connection with the previous lessons is straightforward. On Day 33, I learned about attack patterns such as:

- SYN packets used in port scans
- Long, random-looking DNS domains
- Regular beacon traffic

On Day 35, I looked for these patterns manually.

An IDS/IPS automates this process and does it continuously.

### Takeaway

- **IDS:** Detects suspicious traffic and alerts.
- **IPS:** Detects suspicious traffic and can also block it.
- Both automate the traffic analysis that I previously performed manually.
- They can monitor traffic at a scale that humans cannot.

# IDS vs IPS: Detect vs Prevent

The most important difference between IDS and IPS is where they are placed and what they are allowed to do.

## IDS

An IDS normally watches a **copy of network traffic**.

The actual traffic continues normally, while the IDS receives a copy through methods such as:

- SPAN/mirror ports
- Network TAPs

Because the IDS is watching a copy, it cannot directly stop the original packet.

It can:

- Detect suspicious activity
- Generate alerts
- Log events
- Notify security analysts
- Display events in a dashboard

I can think of an IDS like a **smoke detector**.

It tells me that something is wrong, but it doesn't put out the fire.

---

## IPS

An IPS sits **inline** in the actual traffic path.

Every packet passes through it before reaching its destination.

Because the IPS is inline, it can take action when malicious traffic is detected.

For example, it can:

- Drop malicious packets
- Reset connections
- Block a source
- Stop traffic before it reaches the target

I can think of an IPS like a **sprinkler system**.

It detects the problem and can automatically act on it.

---

## IDS vs IPS

| Feature | IDS | IPS |
|---|---|---|
| Full Name | Intrusion Detection System | Intrusion Prevention System |
| Position | Usually off to the side | Inline |
| Traffic | Watches a copy | Traffic passes through it |
| Detects attacks | Yes | Yes |
| Generates alerts | Yes | Yes |
| Blocks traffic | No | Yes |
| Main risk | Alert overload | False positives can block legitimate traffic |
| Analogy | Smoke detector | Sprinkler system |

### IPS Tradeoffs

IPS is more powerful because it can stop attacks automatically, but this also creates risks.

Because it is inline:

- If the IPS fails, network connectivity can potentially be affected.
- A false positive can block legitimate users or business traffic.
- The system needs to be carefully configured and tuned.

An IDS false positive mainly creates an unnecessary alert.

An IPS false positive can actually stop legitimate traffic.

### Takeaway

IDS watches a copy of traffic and alerts.

IPS sits inline and can block traffic.

Many organisations use both. An IPS can block obvious known threats, while an IDS can monitor deeper traffic and provide alerts for human analysts to investigate.

# How IDS and IPS Decide What's Malicious

IDS and IPS need a way to distinguish malicious traffic from normal traffic.

There are two major approaches:

1. Signature-based detection
2. Anomaly-based detection

---

## 1. Signature-Based Detection

Signature-based detection works similarly to antivirus software.

The system contains a database of known attack patterns.

A signature could describe:

- A known exploit
- A known malware beacon
- A known scanning tool
- A specific malicious byte pattern
- A known attack request

When traffic matches a known signature, the IDS/IPS raises an alert or takes action.

### Advantages

- Fast
- Precise
- Usually produces fewer false positives
- Good at detecting known attacks

### Disadvantage

The main weakness is that it only knows what has already been identified.

A new attack with no existing signature may pass through.

This includes **zero-day attacks**.

Signature databases therefore need regular updates.

---

# 2. Anomaly-Based Detection

Anomaly-based detection works differently.

Instead of looking only for known malicious patterns, it learns what **normal traffic** looks like and detects unusual behaviour.

This connects directly to the baseline work from Day 32.

Examples:

- A server normally communicates with 10 addresses but suddenly communicates with 10,000.
- A system suddenly produces a large traffic spike at 3 AM.
- A host starts using a protocol it has never used before.
- A device suddenly behaves very differently from its normal pattern.

The system flags these deviations for investigation.

### Advantages

- Can detect previously unknown attacks
- Can detect unusual behaviour
- Can potentially identify attacks without a specific signature

### Disadvantages

The biggest problem is **false positives**.

Normal networks are not perfectly predictable.

Something being unusual does not automatically mean it is malicious.

For example:

- A backup running at 2 AM
- A new application
- A developer testing something
- A temporary increase in traffic

All of these could look unusual without actually being attacks.

Anomaly-based systems also need time to establish a baseline.

If the system learns its baseline while an attack is already happening, it could potentially treat the malicious behaviour as normal.

---

# Signature vs Anomaly Detection

| Feature | Signature-Based | Anomaly-Based |
|---|---|---|
| Detects | Known attacks | Deviations from normal |
| Strength | Fast and precise | Can detect unknown behaviour |
| Weakness | Misses new attacks | More false positives |
| Requires signatures | Yes | No |
| Zero-day detection | Limited | Potentially better |
| Main issue | Cannot detect what it doesn't know | Unusual does not always mean malicious |

Modern systems can combine both approaches.

Signature detection handles known threats efficiently, while anomaly detection provides a chance to identify unknown threats.

There is no perfect detection system, which is why human analysts are still important.

### Takeaway

- **Signature-based:** Looks for known malicious patterns.
- **Anomaly-based:** Looks for behaviour that is different from the normal baseline.
- Signature detection is precise but can miss new attacks.
- Anomaly detection can find unknown behaviour but can generate more false positives.
- Modern systems often combine both.

# The False Positive Problem

One of the biggest practical problems with IDS and IPS is not detecting attacks.

It is **not detecting everything else**.

A very sensitive IDS can generate thousands of alerts every day.

Many of those alerts may be completely legitimate.

For example:

- A backup job running at 2 AM
- A developer testing an application
- A new application generating unfamiliar traffic
- A legitimate scanning activity
- A temporary traffic spike

If security analysts receive too many alerts, the real attack can become hidden among the noise.

---

## Alert Fatigue

This can lead to **alert fatigue**.

When analysts constantly receive large numbers of alerts, they can become less responsive to individual alerts.

The lesson material gives the **Target breach** as an example.

Target's security tools detected the attack and generated alerts, but the alerts were missed among the large amount of other activity.

So the problem was not necessarily that detection failed.

The problem was that the important signal was lost in the noise.

---

## How Organisations Handle False Positives

Organisations try to balance:

```text
Too Sensitive
      ↓
Too Many Alerts
      ↓
Analyst Overload
```

and:

```text
Too Lax
      ↓
Too Few Alerts
      ↓
Attacks May Be Missed
```

To manage this, organisations:

- Tune detection rules
- Prioritise alerts by severity
- Reduce unnecessary alerts
- Correlate related events
- Send alerts to systems that aggregate and analyse them

This leads directly to the **SIEM**, which is the next topic.

### Takeaway

The challenge is finding the balance between detecting real attacks and avoiding huge numbers of false positives.

Too many alerts can cause **alert fatigue** and hide important attacks.

This is one of the main reasons security teams use SIEM platforms to aggregate, correlate, and prioritise events.

# Where IDS and IPS Are Used

## Open-Source Tools

### Snort

**Snort** is one of the most well-known IDS/IPS tools.

It was first released in 1998 and became one of the defining tools in this area.

### Suricata

**Suricata** is a modern, high-performance alternative.

It can also use Snort-compatible rules.

### Zeek

**Zeek**, formerly known as **Bro**, takes a different approach.

It focuses heavily on generating detailed network activity logs that can be used for analysis.

# IDS/IPS in Enterprise Networks

In enterprise environments, IDS/IPS functionality is increasingly included inside **next-generation firewalls** rather than being deployed as completely separate appliances.

Examples mentioned in the lesson include:

- Palo Alto
- Fortinet
- Cisco

Modern firewalls can provide:

- Network filtering
- Intrusion prevention
- Threat detection
- Logging
- Other security controls

Cloud providers also offer managed detection services.

Larger organisations may also use **Network Detection and Response (NDR)** platforms.

The basic purpose remains the same:

```text
Watch Traffic
     ↓
Detect Threats
     ↓
Alert or Block
```

---

# Host-Based IDS

Everything discussed so far mainly focuses on **network-based detection**.

There is also **Host-Based Intrusion Detection (HIDS)**.

A HIDS runs directly on an individual machine and watches for suspicious activity on that host.

It can look for things such as:

- Unexpected file changes
- Strange process behaviour
- Signs of compromise
- Suspicious activity on the endpoint

Network-based and host-based detection complement each other.

One watches activity on the network, while the other watches what is happening on individual systems.

---

# IDS/IPS and Small Businesses

For a small business like Maya's shop, running a dedicated IDS appliance may not be practical.

However, she can still benefit from the same technology.

The router or firewall protecting the network may already provide basic IPS features.

A managed security service could also provide detection as the business grows.

The practical approach for a small business is usually:

- Choose networking equipment with security features
- Enable appropriate protections
- Keep the equipment updated
- Use managed security services when needed
