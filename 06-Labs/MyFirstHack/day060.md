# 1. What Is a Package Manager?

A package manager is a tool used to:

- Install software
- Update software
- Remove software

Instead of downloading installers from random websites, I can ask the package manager for software by name.

The package manager then gets it from a configured repository.

Common package managers mentioned in this lesson:

| Linux Distribution | Package Manager |
|---|---|
| Ubuntu / Debian | `apt` |
| Fedora / Red Hat | `yum` / `dnf` |

The commands may differ, but the basic idea is the same.

---

# 2. Repositories

A **repository** is a trusted and curated collection of software maintained by the Linux distribution.

When I install software using `apt`, it normally gets the package from the configured repository rather than from a random website.

```text
Package manager
      ↓
Trusted repository
      ↓
Package
      ↓
Installed software
```

This provides a security advantage because the software comes from a maintained and vetted source.

---

# 3. What Is a Package?

A **package** is software bundled in a format that the package manager can install.

It contains the program and the information needed to install it correctly.

```text
Package
 ├── Program
 └── Information needed for installation
```

---

# 4. Dependencies

Software often depends on other software, libraries, or components.

These are called **dependencies**.

A package manager can automatically work out these dependencies and install what is required.

```text
Program
   ↓
Dependencies
   ↓
Required libraries/components
```

This means I don't have to manually find and install every supporting component myself.

# 5. Important `apt` Commands

| Command | Purpose |
|---|---|
| `apt update` | Refreshes the list of available software and versions |
| `apt upgrade` | Installs newer versions of installed software |
| `apt install <package>` | Installs new software |
| `apt remove <package>` | Removes installed software |
| `apt search <keyword>` | Searches for available software |

System software changes normally require administrative privileges, so these commands are typically used with `sudo`.

## `apt update`

```bash
sudo apt update
```

This refreshes the catalogue of available software and versions.

Important distinction:

```text
apt update
    ↓
Updates the package catalogue

apt upgrade
    ↓
Actually updates installed software
```

`apt update` does **not** itself upgrade the installed software.

## `apt upgrade`

```bash
sudo apt upgrade
```

This installs newer versions of software that are already installed.

This is especially important for security because updates can contain fixes for known vulnerabilities.

## `apt install`

```bash
sudo apt install <package>
```

Installs new software by package name.

## `apt remove`

```bash
sudo apt remove <package>
```

Removes installed software that is no longer needed.

## `apt search`

```bash
apt search <keyword>
```

Searches the available software packages using a keyword.

# 6. Why Software Updates Matter for Security

This was the main security lesson of today.

Software can contain vulnerabilities.

When a vulnerability is discovered, the software developers can release an update containing a fix.

If I don't install that update, my system can remain vulnerable even though a fix already exists.

```text
Vulnerability discovered
        ↓
Developer releases fix
        ↓
Update becomes available
        ↓
I install the update
        ↓
Known vulnerability is fixed
```

If the update is not installed:

```text
Vulnerability
      ↓
Fix available
      ↓
Update not applied
      ↓
System remains vulnerable
```

Once a vulnerability is publicly known and fixed, attackers can actively look for systems that have not applied the update.

This is why keeping software updated is such an important security habit.

---

# 7. `apt upgrade` as a Security Action

Updating software is not just system maintenance.

It is also a security action.

Every time I apply available updates, I may be closing known security holes.

```text
Old software
     ↓
Known vulnerability
     ↓
Security update available
     ↓
apt upgrade
     ↓
Updated software
     ↓
Reduced exposure
```

A major security lesson from today is:

> **Keep systems patched and up to date.**

---

# 8. Updates and the Risk of Breaking Things

There is still a balance to consider.

Updates can occasionally cause problems, such as:

- A new version behaving differently
- Something depending on older behaviour no longer working

This is why critical production environments may test updates before applying them widely.

However, the lesson emphasises that for most normal situations, the risk of leaving known vulnerabilities unpatched is much greater than the occasional problems caused by updating.

# 9. The Danger of Untrusted Software Sources

Linux allows software to be installed from many different sources.

The safest default is the distribution's trusted repository.

Software can also come from:

- A package downloaded from a website
- A third-party repository
- An installation script from the internet
- Software compiled from source

The further I move away from a curated repository, the more carefully I need to consider the source.

```text
Trusted repository
       ↓
Higher trust

Third-party source
       ↓
More trust required

Random installation script
       ↓
Higher risk
```

# 10. Installation Scripts and Day 56

This connects directly to the file-investigation skills from Day 56.

A common compromise technique is convincing someone to run an installation command or script from an untrusted source.

For example:

```text
"Paste this command into your terminal to install our tool."
```

If the command downloads and executes a malicious script, the attacker may gain the ability to change the system.

The defensive mindset is:

```text
Unknown installation command
        ↓
Check the source
        ↓
Understand what it does
        ↓
Decide whether it is trustworthy
        ↓
Run only when appropriate
```

The same principle from file investigation applies:

> **Don't run untrusted things.**

Installing software means running code that can change the system, so software installation should be treated carefully.

# 11. Trust and Provenance

An important concept from this lesson is **provenance**.

Before installing software, ask:

> **Where did this software come from, and do I trust that source?**

The package manager's repository is the high-trust default.

If I need software that isn't available there, I should be deliberate about where it comes from and prefer official sources.

```text
Where did it come from?
          ↓
Do I trust the source?
          ↓
Is it necessary?
          ↓
Install carefully
```

This is an important part of software hygiene.

---

# 12. Software Hygiene

**Software hygiene** means maintaining software in a secure and controlled way.

The lesson identifies several important habits:

### 1. Keep software updated

Apply security updates promptly.

```text
Updated software
      ↓
Known vulnerabilities fixed
```

### 2. Install from trusted sources

Prefer the distribution's curated repository.

### 3. Remove software you don't need

Unused software is still part of the system's attack surface.

```text
Unnecessary software
       ↓
Potential vulnerabilities
       ↓
Additional attack surface
```

Removing unnecessary software reduces that exposure.

### 4. Know what is installed

Being aware of the software on a system helps me notice something that shouldn't be there.

These habits together form the foundation of software hygiene.

---

# 13. Software Hygiene and Attack Surface

This connects with the earlier lessons about **least privilege**.

Least privilege reduces what each part of a system is allowed to do.

Software hygiene reduces unnecessary software and keeps installed software current and trusted.

```text
Least privilege
      ↓
Reduce what components can do

Software hygiene
      ↓
Reduce what components are present
      ↓
Keep them updated and trusted
```

Both follow the same defensive idea:

> **Keep systems minimal, current, and trusted.**
