# Network Segmentation
**Day 34 of 90 · How Networks Actually Work**
**Date Completed:** 09 August 2026


## Why one breach shouldn't mean total loss

Network segmentation is the practice of splitting a network into separate zones so that a compromise in one area does not automatically give an attacker access to everything else.

The main idea is **containment**.

On a flat network, devices can often communicate with many other devices. If one laptop, IoT device, or guest device is compromised, the attacker may have a path toward important systems.

On a segmented network, the compromised device is trapped inside its zone. To move further, the attacker has to cross additional controls. Each barrier provides another opportunity to detect and stop the attacker.

> **Segmentation turns "an attacker got in" from a catastrophe into an incident.**

The goal is not to make breaches impossible. The goal is to make sure that **one breach does not become a total loss**.

---

## 1. How networks get segmented

### Subnets

A subnet divides a network into separate IP ranges.

Example:

```text
192.168.10.0/24 → Marketing
192.168.20.0/24 → Finance
192.168.30.0/24 → Servers
```

Devices in different subnets generally need a router or Layer 3 device to communicate. This creates a natural point where traffic can be controlled.

```text
Marketing Subnet
      |
      v
    Router
      |
      v
Finance Subnet
```

---

### VLANs

**VLANs (Virtual Local Area Networks)** divide one physical network into multiple logical networks.

```text
                 Physical Switch
                       |
       +---------------+---------------+
       |               |               |
    VLAN 10          VLAN 20         VLAN 30
    Marketing        Finance          Servers
```

The same physical switch can carry multiple isolated logical networks. Devices on different VLANs cannot directly communicate simply because they share the same switch. Communication between VLANs can instead be routed and controlled.

---

### Firewalls between zones

Firewalls enforce what traffic is allowed to cross between network zones.

Example:

```text
Marketing Zone
      |
   Firewall
      |
      +----> Internet       ALLOW
      +----> File Server    ALLOW
      +----> Payment System DENY
```

Segmentation becomes a real security control when firewall rules determine which connections are permitted.

The key principle is:

> **Only allow communication that is actually required.**

---

### DMZ

A **DMZ (Demilitarised Zone)** is a separate segment for systems that must be reachable from the public internet.

Examples:

- Web servers
- Mail servers
- Other public-facing services

```text
Internet
    |
 Firewall
    |
   DMZ
  /   \
Web   Mail
 |     |
 +-----+
    |
Another Firewall
    |
Internal Network
```

If a public-facing server is compromised, the attacker is initially contained in the DMZ instead of immediately being inside the internal network.

The DMZ is therefore a deliberate **sacrifice zone** for systems that require public exposure.

---

### Guest networks

A guest network gives visitors internet access while separating them from trusted internal devices.

```text
                 Router
                   |
        +----------+----------+
        |                     |
    Main Wi-Fi            Guest Wi-Fi
        |                     |
 Trusted Devices           Guests
        |                     |
 Internal Network          Internet
```

Guest devices should not freely access laptops, servers, printers, cameras, or other trusted internal devices.

---

## 2. Layering segmentation controls

A mature network may use several mechanisms together:

```text
Subnets
   ↓
VLANs
   ↓
Firewalls
   ↓
DMZ
   ↓
Guest / Untrusted Networks
```

Each layer creates another barrier.

The objective is to make movement between zones:

- Controlled
- Limited
- Slow
- Detectable

This makes **lateral movement** harder for an attacker.

## 3. IoT segmentation

IoT devices include:

- Smart TVs
- Cameras
- Doorbells
- Thermostats
- Smart speakers
- Other connected devices

These devices can be security risks because they may receive fewer updates, use weak default credentials, or be difficult to patch.

A smart camera has no reason to communicate with a work laptop.

Therefore, IoT devices should ideally be placed on a separate network:

```text
             Home Network
                  |
        +---------+---------+
        |                   |
     Trusted             IoT Zone
      Zone                  |
        |              +----+----+
     Laptop           Camera   Smart TV
```

The IoT network can still have internet access while limiting access to trusted devices.

### Mirai example

The lesson uses the **2016 Mirai botnet** as an example of the dangers of insecure and insufficiently segmented IoT devices.

Mirai weaponised large numbers of vulnerable IoT devices and used them in large-scale DDoS attacks.

The important lesson is:

> Insecure devices should not automatically have broad network access.

---

## 4. Operational Technology (OT)

**Operational Technology (OT)** refers to systems used to control physical processes.

Examples include:

- Factories
- Power plants
- Water treatment facilities
- Industrial environments

OT systems are especially sensitive because they may control physical machinery.

A concern is the connection between:

```text
IT Network
    |
    v
OT Network
    |
    v
Physical Equipment
```

OT environments may also contain older systems that cannot easily be patched without interrupting production.

Therefore, **IT/OT segmentation** is critical.

A compromised office workstation should not automatically provide access to industrial control systems.

## 5. Maya's small shop

Maya's shop contains:

- A till/payment system
- Security cameras
- A back-office laptop
- Customer Wi-Fi

Putting everything on one flat network creates unnecessary risk.

A better design is:

```text
                    Router / Firewall
                           |
          +----------------+----------------+
          |                |                |
       Payment            IoT            Guest
        Zone              Zone            Zone
          |                |                |
        Till           Cameras        Customer Wi-Fi
```

### Payment system

The payment system handles sensitive transactions and should be isolated from unnecessary devices.

### Cameras

Cameras are IoT devices and should not need access to payment systems.

### Customer Wi-Fi

Customers should have internet access without access to internal business systems.

### Back-office systems

Business computers should be protected from guest and untrusted devices.

The important lesson is that small businesses do not necessarily need a huge enterprise architecture. Even basic network separation can significantly reduce risk.

---

## 6. Where segmentation matters most

Segmentation is especially important when **insecure or critical systems share a network with valuable systems**.

Important examples:

### IoT

Potentially insecure devices should be isolated.

### OT

Industrial control systems should be separated from ordinary IT systems.

### Payment systems

Payment-processing systems should be separated from general-purpose systems.

### Guest devices

Untrusted visitor devices should not have access to internal resources.

The common principle is:

> **Separate what doesn't need to talk.**

## 7. Segmentation and least privilege

The security principle behind network segmentation is **least privilege applied to networks**.

Least privilege means giving a user or system only the permissions required to perform its job.

The same idea can be applied to network connectivity.

Instead of asking:

> "How can these systems communicate?"

Ask:

> **"Do these systems actually need to communicate?"**

If they do not need to communicate, access should be restricted.

Example:

```text
Marketing Laptop
      |
      +----> Internet       ALLOW
      |
      +----> File Server    ALLOW
```

It does not need:

```text
Marketing Laptop
      |
      +----> Payment System
      +----> Database
      +----> Industrial OT
```

Those unnecessary paths should be blocked.

---

## 8. Default deny

Segmentation connects directly to **default deny**.

Instead of:

```text
Allow Everything
      ↓
Block known bad
```

a stronger approach is:

```text
Deny by default
      ↓
Allow only required traffic
```

Example:

```text
Marketing → Internet       ALLOW
Marketing → File Server    ALLOW
Marketing → Database       DENY
Marketing → Payment        DENY
Marketing → OT             DENY
```

This reduces unnecessary attack paths.

---

## 9. Segmentation and lateral movement

After compromising a machine, an attacker may attempt to move through the network. This is called **lateral movement**.

### Flat network

```text
Compromised Laptop
       |
       +----> Server
       +----> Database
       +----> Payment
       +----> Other PCs
```

### Segmented network

```text
Compromised Laptop
       |
       v
   User Zone
       |
    Firewall
       |
       X
       |
Payment / Server / OT Zones
```

The attacker must overcome additional controls before reaching another zone.

This makes the attack:

- Harder
- Slower
- More visible
- Easier to contain

---

## 10. Segmentation does not mean perfect security

Segmentation does not guarantee that an attacker can never move between zones.

Instead, it creates **barriers**.

The objective is:

```text
Compromise
    ↓
Containment
    ↓
Detection
    ↓
Blocking
    ↓
Reduced Damage
```

A strong network design assumes that some systems may eventually be compromised and limits the consequences when that happens.

---

## 11. Zero Trust

The lesson connects segmentation to **Zero Trust**.

Traditional segmentation can still assume that devices inside the same zone are trusted.

Zero Trust takes the idea further:

> **Do not trust anything by default. Verify every access request.**

Conceptually:

```text
Any Device
    ↓
  Verify
    ↓
 Authorize
    ↓
Allow only required access
```

Zero Trust extends the principle of least privilege beyond simple network boundaries.

The lesson notes that Zero Trust will be studied directly later in the course.

## 12. Example segmented architecture

A more complete network could look like:

```text
                         INTERNET
                             |
                             v
                        Edge Firewall
                             |
             +---------------+---------------+
             |                               |
             v                               v
            DMZ                         Internal Firewall
             |                               |
       +-----+-----+             +-----------+-----------+
       |           |             |           |           |
     Web         Mail          Users       Servers      IoT
   Server       Server           |           |           |
                                 |           |           |
                              VLAN 10      VLAN 20      VLAN 30
                                 |
                                 v
                              Guest
                              VLAN 40
```

Each zone has a specific purpose and traffic between zones can be controlled.

## 13. Security benefits

### 1. Limits blast radius

A compromised system cannot automatically reach the entire network.

### 2. Reduces attack surface

Unnecessary communication paths are removed.

### 3. Limits lateral movement

Attackers have to cross additional security controls.

### 4. Improves detection

Attempts to cross zones can generate useful security events.

### 5. Protects critical systems

Important systems can be isolated from general-purpose devices.

### 6. Supports least privilege

Each zone receives only the network access it requires.

### 7. Improves containment

Security teams can isolate compromised areas more effectively.
