# What is DNS?

DNS (Domain Name System) is often called the **phonebook of the internet**.

Humans remember names like:

```
google.com
reddit.com
github.com
```

But computers communicate using IP addresses like:

```
142.250.191.46
```

DNS converts domain names into IP addresses so computers know where to connect.

Without DNS, we would have to remember the IP address of every website we visit.

---

# The Complete DNS Lookup Process

I learned that when I type:

```
google.com
```

my computer doesn't instantly know Google's IP address.

Instead, a series of lookups happen behind the scenes.

---

## Step 1 - Browser Cache

The browser first checks whether it already knows the IP address.

If I recently visited the website, Chrome or Firefox already has the answer stored.

No DNS request is needed.

---

## Step 2 - Operating System Cache

If the browser doesn't know the answer, Windows or Linux checks its own DNS cache.

If found, the lookup stops here.

---

## Step 3 - Router Cache

If my computer doesn't know, it asks my home router.

Since everyone connected to the same Wi-Fi shares the router, another device may already have requested the same website.

---

## Step 4 - ISP Recursive Resolver

If the router also doesn't know, the request goes to my ISP's DNS server.

Examples:

- Airtel
- Jio
- BSNL

The ISP's recursive resolver now starts searching for the answer.

---

## Step 5 - Root DNS Server

The resolver asks one of the Internet Root Servers.

The root server doesn't know Google's IP.

Instead, it says:

> "For anything ending in .com, ask the .com servers."

---

## Step 6 - Top Level Domain (TLD) Server

The resolver now contacts the .com server.

The .com server replies:

> "For google.com, ask Google's authoritative DNS server."

---

## Step 7 - Authoritative DNS Server

Finally, Google's DNS server responds with the correct IP address.

Example:

```
142.250.191.46
```

This is the official source of truth.

---

## Step 8 - Response Returns

The answer now travels back through:

- Recursive Resolver
- Router
- Operating System
- Browser

Finally, the browser can open a connection to Google.

---

# DNS Lookup Flow

```
Browser
    │
    ▼
Browser Cache
    │
    ▼
OS Cache
    │
    ▼
Router Cache
    │
    ▼
ISP Recursive Resolver
    │
    ▼
Root DNS Server
    │
    ▼
TLD Server (.com)
    │
    ▼
Authoritative DNS Server
    │
    ▼
Returns IP Address
    │
    ▼
Browser connects to Website
```

# DNS Caching

One of the biggest concepts I learned today was **DNS Caching**.

Without caching, every website visit would require all eight lookup steps.

That would overload DNS servers across the world.

Instead, almost every device caches DNS responses.

Caching happens at multiple layers:

- Browser
- Operating System
- Router
- ISP DNS Resolver

Because of this, most DNS requests never reach the authoritative server.

---

# TTL (Time To Live)

Every DNS record has a TTL value.

TTL tells devices:

> "How long should this DNS answer be trusted before asking again?"

Example:

```
TTL = 300 seconds
```

For the next five minutes, everyone uses the cached answer.

After TTL expires, a fresh lookup happens.

---

# Why Caching is Important

Advantages:

- Faster website loading
- Less internet traffic
- Reduced load on DNS servers
- Better overall performance

Without caching, the internet would become extremely slow.

---

# DNS Security Risks

The same caching system that improves speed can also become a security problem.

If an attacker manages to poison a DNS cache, everyone using that cache receives the fake IP address.

---

# DNS Attacks

## 1. DNS Spoofing / Cache Poisoning

The attacker tricks a DNS resolver into storing a fake IP address.

Instead of:

```
google.com
↓

142.250.191.46
```

The resolver returns:

```
google.com
↓

203.xxx.xxx.xxx
```

The victim is redirected to a malicious website without realizing it.

---

## 2. DNS Hijacking

Instead of attacking the cache, the attacker changes the DNS server itself.

Example:

Changing the router's DNS from

```
8.8.8.8
```

to

```
Attacker DNS Server
```

Now every lookup passes through the attacker's server.

---

## 3. DNS Tunneling

Attackers hide stolen information inside DNS requests.

Since almost every firewall allows DNS traffic, malware can secretly communicate through DNS.

This technique is often used for:

- Data Exfiltration
- Command & Control
- Malware Communication

---

## 4. Typosquatting

Instead of attacking DNS directly, attackers register domains that look similar to legitimate ones.

Examples:

```
google.com

gooogle.com

paypa1.com

arnazon.com
```

Users accidentally visit these fake websites and may enter their credentials.

---

# Why Defenders Monitor DNS

DNS logs reveal many attacks.

Security teams watch for:

- Large numbers of DNS requests
- Unknown domains
- Suspicious DNS traffic
- Malware communication
- DNS tunneling

Many attacks are detected by analyzing unusual DNS activity.

# Practical Task

Today I used **nslookup** to perform real DNS queries.

Examples:

```bash
nslookup google.com
```

```bash
nslookup reddit.com
```

```bash
nslookup cnn.com
```

I also queried Google's Public DNS:

```bash
nslookup google.com 8.8.8.8
```

And Cloudflare's DNS:

```bash
nslookup google.com 1.1.1.1
```

This showed me that I can choose which DNS resolver I trust instead of using my ISP's default DNS server.

---

# DNS Cache Demonstration

I also observed DNS caching using Chrome Developer Tools.

Steps:

- Open Chrome
- Press F12
- Open Network Tab
- Enable "Disable Cache"
- Visit a website
- Check DNS Lookup time
- Reload after enabling cache

The first request took measurable DNS lookup time.

The second request was almost instant because the DNS information was already cached.

This made it easy to see how caching improves website loading speed.
