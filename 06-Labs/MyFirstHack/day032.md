# What is Packet Reading?

Packet reading means understanding the complete story of network communication.

Instead of asking:

> "What packet is this?"

A security analyst asks:

> "Why was this packet sent?"
>
> "What happened before it?"
>
> "What happened after it?"
>
> "Is this behaviour normal?"

Packets are like individual words.

A TCP conversation is the complete sentence.

Reading packets means understanding the sentence instead of just recognizing words.

---

# Why Packet Reading Matters

During an investigation, analysts rarely inspect every packet.

Instead they:

- Follow conversations
- Build timelines
- Look for unusual behaviour
- Compare traffic against normal network behaviour

Reading packets allows analysts to determine:

- Was the connection successful?
- Did authentication fail?
- Was malware communicating?
- Was someone scanning ports?
- Was sensitive information exposed?
- Did an attacker establish persistence?

# Understanding a TCP Conversation

Every TCP communication follows a lifecycle.

```
Client
   │
   │ SYN
   ▼
Server
   │
   │ SYN-ACK
   ▼
Client
   │
   │ ACK
   ▼

Connection Established

↓

Data Transfer

↓

Connection Closed
```

A TCP conversation consists of three stages.

---

# Stage 1 — TCP Three-Way Handshake

Before any communication starts, both devices must establish a connection.

The handshake consists of three packets.

## Step 1 — SYN

The client sends:

```
SYN
```

Meaning:

> "I'd like to establish a connection."

---

## Step 2 — SYN-ACK

The server replies:

```
SYN-ACK
```

Meaning:

> "I received your request and I'm ready."

---

## Step 3 — ACK

The client responds:

```
ACK
```

Meaning:

> "Connection confirmed."

The connection is now established.

---

# Stage 2 — Data Transfer

After the handshake, the devices exchange data.

Example:

```
Browser
↓

HTTPS Request

↓

Web Server

↓

HTTPS Response

↓

Browser
```

For HTTPS traffic, Wireshark cannot decrypt the contents.

However, it still displays:

- Source IP
- Destination IP
- Source Port
- Destination Port
- Packet Size
- Packet Timing
- TCP Flags
- Direction of communication

This allows analysts to understand communication even without seeing the encrypted data.

---

# Stage 3 — TCP Connection Teardown

TCP normally closes connections politely.

Sequence:

```
FIN

↓

ACK

↓

FIN

↓

ACK
```

Meaning:

Both devices have completed communication.

---

# Reset (RST)

Sometimes a connection doesn't close normally.

Instead, Wireshark shows:

```
RST
```

RST means:

- Connection rejected
- Connection terminated immediately
- Service unavailable
- Unexpected interruption

RST packets are not always malicious.

However, excessive resets may indicate:

- Network problems
- Service crashes
- Port scanning
- Firewall blocking
- Attack activity

---

# Following a TCP Stream

One of Wireshark's most useful features is:

```
Right Click Packet

↓

Follow

↓

TCP Stream
```

Instead of viewing thousands of unrelated packets, Wireshark isolates one complete conversation.

This makes investigations much easier.

A TCP Stream contains:

- Handshake
- Requests
- Responses
- Connection teardown

Everything related to one conversation.

# Understanding Normal Traffic

One of today's biggest lessons was:

> You cannot detect abnormal traffic until you know what normal traffic looks like.

Professional analysts spend time learning normal behaviour before investigating attacks.

---

## Normal Pattern 1 — DNS Comes First

Normally a computer performs:

```
DNS Query

↓

DNS Response

↓

TCP Connection

↓

HTTPS Traffic
```

The device first asks:

> "What is the IP address of google.com?"

Only after receiving the IP does it establish a connection.

If traffic starts directly to an IP address without a DNS lookup, it may indicate:

- Cached DNS
- Hardcoded IP
- Malware
- Manual configuration

It isn't always malicious, but it deserves investigation.

---

## Normal Pattern 2 — Connections Finish Properly

Healthy TCP communication looks like:

```
SYN

↓

SYN-ACK

↓

ACK

↓

Data

↓

FIN

↓

ACK
```

Abnormal behaviour includes:

- Many SYN packets
- No responses
- Numerous RST packets
- Half-open connections

These may indicate:

- Server failure
- Firewall issues
- Port scanning
- Network attacks

---

## Normal Pattern 3 — Familiar Destinations

Most traffic on a normal computer goes to:

- Google
- Microsoft
- Apple
- Cloudflare
- GitHub
- ISP DNS servers
- Windows Update
- Linux repositories

Unknown external IPs should always be reviewed.

---

## Normal Pattern 4 — Background Traffic

Computers continuously communicate even when idle.

Examples include:

- DNS lookups
- DHCP renewals
- NTP time synchronization
- ARP requests
- mDNS advertisements
- Software update checks

These create predictable network patterns.

---

## Normal Pattern 5 — Most Traffic is Encrypted

Modern networks primarily use:

```
HTTPS

Port 443
```

Seeing encrypted HTTPS traffic is normal.

Seeing sensitive data sent in plain HTTP should raise concerns.

# Important Packet Fields

While every packet contains dozens of fields, only a few are required for most investigations.

---

# TCP Flags

TCP Flags describe the state of communication.

## SYN

Starts a connection.

---

## ACK

Acknowledges received packets.

---

## FIN

Gracefully ends communication.

---

## RST

Terminates communication immediately.

---

## PSH

Pushes received data immediately to the application.

---

These flags tell the story of a TCP conversation.

---

# Ports

Ports identify the service.

Common ports:

| Port | Service |
|-------|----------|
| 22 | SSH |
| 53 | DNS |
| 80 | HTTP |
| 443 | HTTPS |
| 3389 | RDP |

Destination ports identify the target service.

Source ports are usually randomly assigned by the client.

---

# Packet Timing

Time is extremely useful during investigations.

Humans generate irregular traffic.

Machines generate highly regular traffic.

Example:

```
Every 30 seconds

↓

HTTPS Packet

↓

Same Destination
```

Regular timing often indicates automation.

---

# Packet Length

Packet size reveals communication type.

Large packets often indicate:

- Downloads
- Videos
- File transfers

Small packets often indicate:

- Keepalive traffic
- Command-and-Control communication
- Malware beaconing

---

# Wireshark Info Column

The Info column provides a human-readable summary.

Examples:

DNS:

```
Standard query A google.com
```

HTTP:

```
GET /index.html
```

TLS:

```
Client Hello
```

This allows quick understanding without opening packet details.

# Reading Packets for Security

Packet analysis is essential for threat detection.

Analysts usually:

- Filter traffic
- Follow TCP streams
- Compare against normal behaviour
- Investigate anomalies

---

# Detecting Port Scans

Pattern:

```
Attacker

↓

SYN

↓

Port 20

↓

RST

↓

SYN

↓

Port 21

↓

RST

↓

SYN

↓

Port 22

↓

RST
```

Many SYN packets sent to multiple ports indicate reconnaissance.

---

# Detecting Suspicious DNS

Normal:

```
google.com
github.com
microsoft.com
```

Suspicious:

```
x7f3k9q2bv8.example.com
```

Long random domains often indicate:

- Malware
- DNS tunnelling
- Data exfiltration

---

# Detecting Malware Beacons

Compromised systems often communicate at fixed intervals.

Example:

```
Every 60 Seconds

↓

HTTPS Connection

↓

Same External IP
```

Humans do not generate perfectly timed traffic.

Machines do.

---

# Detecting Plaintext Data

Sensitive information should always be encrypted.

If Wireshark displays:

- Usernames
- Passwords
- API Keys
- Credit Card Data

in readable text, this represents a significant security issue.

## Common Display Filters

Show DNS traffic

```
dns
```

Show TCP traffic

```
tcp
```

Show HTTP traffic

```
http
```

Show HTTPS traffic

```
tcp.port == 443
```

Show DNS port

```
udp.port == 53
```

Traffic involving a specific IP

```
ip.addr == 192.168.1.100
```

Combine filters

```
dns && ip.addr == 192.168.1.1
```
