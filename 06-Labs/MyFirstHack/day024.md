# Overview

Today's lesson focused on the **Domain Name System (DNS)**, one of the most important services on the Internet.

Humans remember names like:

```
google.com
github.com
wikipedia.org
```

Computers communicate using IP addresses such as:

```
142.250.183.78
```

DNS acts as the translator between these two, allowing users to browse the Internet using easy-to-remember domain names instead of numeric IP addresses.

Without DNS, users would have to remember IP addresses for every website they visit.

---

# What is DNS?

**DNS (Domain Name System)** is a distributed naming system that translates **domain names into IP addresses**.

Example:

```
google.com
        │
        ▼
142.250.xxx.xxx
```

Whenever a website is accessed, the device first performs a DNS lookup before making any network connection.

DNS is often called the **Internet's Phonebook** because it maps names to numbers.

---

# Why DNS is Important

Computers communicate using IP addresses, not names.

Instead of remembering:

```
172.217.160.78
```

we simply type:

```
google.com
```

DNS performs the conversion automatically.

---

# DNS Resolution Process

When a user enters:

```
myfirsthack.com
```

the following steps occur.

## Step 1 — Browser Cache

The browser checks whether it already knows the IP address.

If found:

```
Use Cached Result
```

No DNS lookup is needed.

---

## Step 2 — Operating System Cache

If the browser cache misses, the operating system checks its DNS cache.

Again, if found:

```
Use Cached Result
```

---

## Step 3 — Recursive Resolver

If no cached result exists, the computer sends a DNS query to a **Recursive Resolver**.

Usually provided by:

- ISP
- Cloudflare (1.1.1.1)
- Google (8.8.8.8)

The resolver performs the lookup on behalf of the client.

---

# DNS Resolution Hierarchy

If the recursive resolver does not already know the answer, it follows a hierarchy.

```
User
 │
 ▼
Recursive Resolver
 │
 ▼
Root Server
 │
 ▼
TLD Server (.com)
 │
 ▼
Authoritative Name Server
 │
 ▼
IP Address
```

---

## Step 1 — Root Server

Question:

```
Who manages ".com"?
```

The root server replies with the addresses of the **.com Top-Level Domain (TLD)** servers.

---

## Step 2 — TLD Server

Question:

```
Who is authoritative for myfirsthack.com?
```

The TLD server replies with the domain's authoritative name servers.

Example:

```
ns1.example.com
ns2.example.com
```

---

## Step 3 — Authoritative Server

Question:

```
What is the IP address of myfirsthack.com?
```

The authoritative server replies with the correct IP address.

---

## Step 4 — Caching

The recursive resolver stores the result in its cache.

Future users requesting the same domain receive the answer much faster.

---

## Step 5 — Browser Connects

The browser now has the IP address and begins establishing a network connection.

---

# DNS Caching

Every DNS response includes a **TTL (Time To Live)**.

TTL specifies how long the answer can remain in cache before a new lookup is required.

Benefits:

- Faster browsing
- Lower DNS traffic
- Reduced server load

---

# DNS Runs on Port 53

Traditional DNS uses:

```
UDP Port 53
```

Sometimes:

```
TCP Port 53
```

TCP is typically used for larger responses or zone transfers.

---

# Why DNS is Frequently Attacked

DNS was created in **1983**, long before Internet security became a major concern.

The protocol prioritizes:

- Speed
- Simplicity

rather than strong security.

---

# Common DNS Weaknesses

## Plain Text Communication

Traditional DNS is not encrypted.

Anyone between the client and resolver may be able to observe DNS queries.

Attackers can learn:

- Websites visited
- Services accessed
- Network activity

---

## Cache Poisoning

Attackers inject false DNS records into a resolver's cache.

Result:

```
google.com
        │
        ▼
Attacker's IP
```

Every user relying on that resolver is redirected until the cache expires.

---

## DNS Hijacking

Instead of poisoning the cache, attackers modify DNS records themselves.

Possible targets include:

- Registrar accounts
- Authoritative DNS servers
- Recursive resolvers

Users are redirected to malicious websites.

---

## DNS Rebinding

A more advanced attack where DNS responses change rapidly.

The attack tricks a browser into communicating with internal devices, such as:

- Routers
- NAS devices
- Internal web servers

---

# DNS Security Improvements

Several technologies improve DNS security.

---

## DNSSEC

DNS Security Extensions (DNSSEC)

Purpose:

Digitally signs DNS records.

Benefits:

- Prevents forged DNS responses
- Verifies authenticity

---

## DNS over HTTPS (DoH)

Encrypts DNS queries using HTTPS.

Benefits:

- Prevents DNS snooping
- Improves privacy

Runs over:

```
HTTPS (Port 443)
```

---

## DNS over TLS (DoT)

Also encrypts DNS traffic.

Uses:

```
TLS
```

instead of traditional DNS.

---

# MyEtherWallet DNS Attack (2018)

One of the most well-known DNS attacks occurred in **2018**.

Attack sequence:

```
BGP Hijack
        │
        ▼
DNS Requests Redirected
        │
        ▼
Fake DNS Responses
        │
        ▼
Users Visit Fake Website
        │
        ▼
TLS Warning Appears
        │
        ▼
Users Ignore Warning
        │
        ▼
Wallet Credentials Stolen
```

Approximately:

```
215 ETH
```

was stolen during the attack.

---

# Lessons from the Attack

The incident demonstrated several important security lessons.

- DNS depends on lower-layer routing (BGP).
- Browser certificate warnings should never be ignored.
- DNSSEC helps prevent forged DNS responses.
- HSTS reduces the risk of users bypassing certificate warnings.

# DNS Records

DNS stores different types of information using record types.

---

## A Record

Maps:

```
Domain Name
        │
        ▼
IPv4 Address
```

Example:

```
example.com
↓

93.184.216.34
```

---

## AAAA Record

Maps a domain to an IPv6 address.

---

## MX Record

Specifies which mail servers receive email.

Example:

```
gmail.com
↓

Mail Server
```

---

## NS Record

Lists the authoritative name servers responsible for the domain.

Example:

```
ns1.example.com
ns2.example.com
```

---

## TXT Record

Stores text information.

Common uses:

- SPF
- DKIM
- DMARC
- Domain Verification

The lesson explains that Maya's online business depends on several important DNS records.

These include:

- A Record

without ever compromising her web server.

# Protecting a Domain

Recommended protections include:

- Enable Multi-Factor Authentication (MFA)
- Use Registrar Lock
- Review WHOIS information
- Limit publicly available personal information

# Practical Commands

Linux / macOS

Lookup a domain:

```bash
dig wikipedia.org
```

Using Cloudflare DNS:

```bash
dig @1.1.1.1 wikipedia.org
```

Using Google DNS:

```bash
dig @8.8.8.8 wikipedia.org
```

Lookup Mail Servers:

```bash
dig wikipedia.org MX
```

Lookup Name Servers:

```bash
dig wikipedia.org NS
```

Lookup TXT Records:

```bash
dig wikipedia.org TXT
```

Lookup IPv6 Address:

```bash
dig wikipedia.org AAAA
```

---

Windows Command Prompt

```cmd
nslookup wikipedia.org
```

Cloudflare

```cmd
nslookup wikipedia.org 1.1.1.1
```

Google

```cmd
nslookup wikipedia.org 8.8.8.8
```
