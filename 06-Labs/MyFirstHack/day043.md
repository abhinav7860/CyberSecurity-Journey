## The Protocol Nobody Blocks

DNS is one of the most important protocols on a network because almost everything depends on it.

Firewalls usually allow DNS traffic because blocking it would break normal internet usage. DNS tunneling takes advantage of this trust by hiding data inside DNS queries and responses.

The main lesson is:

> **Attackers can abuse trusted and necessary protocols to create covert communication channels.**

### Takeaway

DNS tunneling hides data inside DNS traffic to get through security controls that allow DNS.

It can be used for:

- Data exfiltration
- Command and control
- Covert communication

---

## How Data Is Hidden in DNS

DNS queries contain attacker-controlled text in the domain name.

For example, if an attacker controls:

```text
evil.com
```

malware could encode information into a subdomain:

```text
data-here-encoded.evil.com
```

The victim's machine sends the DNS query normally.

The request travels through the DNS infrastructure until it reaches the attacker's authoritative DNS server.

The attacker can then read the encoded information from the subdomain.

The response can also contain encoded information, creating a two-way communication channel.

```text
Victim
   |
   | DNS query containing encoded data
   ↓
DNS Resolver
   |
   ↓
Attacker's DNS Server
   |
   | DNS response containing data
   ↓
Victim
```

The technique is slow compared with normal network communication because DNS names can only carry a limited amount of information.

However, it can still work when other outbound channels are blocked.

### Main Uses

**Data Exfiltration** — stolen information can be slowly sent outside the network using DNS queries.

**Command and Control** — malware can use DNS to receive instructions from an attacker and send information back.

### Takeaway

DNS tunneling turns normal-looking DNS requests into a covert communication channel.

## What DNS Tunneling Looks Like

DNS tunneling can leave several unusual patterns.

### 1. Long and Random-Looking Domain Names

Normal DNS queries usually contain recognisable domain names.

Tunneling may generate long, random-looking subdomains containing encoded data.

Example:

```text
x7f3k9q2bv8h4m1z.evil.com
```

### 2. Abnormally High DNS Volume

Because each DNS query can only carry a limited amount of data, an attacker may need to send many queries.

A workstation suddenly making hundreds or thousands of queries to subdomains of one domain can be suspicious.

### 3. Unusual DNS Record Types

DNS tunneling can make heavier use of record types such as:

```text
TXT
```

because TXT records can contain text data.

### 4. Many Queries to One Strange Domain

One of the strongest clues is concentration.

```text
a8f3kd.evil.com
x72k91.evil.com
p91jd2.evil.com
m2k8sd.evil.com
```

A large number of strange subdomains belonging to the same domain can indicate tunneling.

## Detecting DNS Tunneling

This is where the previous lessons connect together.

### IDS

An IDS can use signatures and traffic patterns to identify suspicious DNS activity.

### SIEM

A SIEM can correlate:

- DNS query volume
- Domains
- Source devices
- Query patterns
- Unusual record types

### Logs

DNS logs provide the raw information needed for investigation.

### Analyst

The analyst compares the activity against what normal DNS traffic looks like.

The important point is:

> **The defence isn't simply blocking DNS. The defence is monitoring DNS.**

### Takeaway

DNS tunneling can be detected through:

- Long random-looking domains
- High DNS query volume
- Unusual record types
- Large numbers of queries to one domain
- IDS signatures
- SIEM correlation
- DNS logs
- Baseline analysis

## Why DNS Tunneling Matters

DNS tunneling teaches several important security lessons.

### Trust Creates Attack Surface

DNS is trusted because it is necessary.

Attackers can abuse protocols that security systems have to allow.

### You Can't Block Everything

A simple solution like:

> "Just block DNS."

doesn't work because DNS is required for normal network operation.

This is why monitoring and detection are important.

### Covert Channels

DNS tunneling is one example of a broader category called **covert channels**.

Attackers can try to hide malicious communication inside trusted services such as:

- DNS
- HTTPS
- Cloud services
- Social media APIs

The idea remains:

> **Hide malicious activity inside traffic that looks legitimate.**

## Important Terms

### DNS Tunneling
A technique that hides data inside DNS queries and responses to create a covert communication channel.

### Data Exfiltration
Moving stolen data from a compromised system to an external location.

### Command and Control (C2)
Communication between malware and the attacker controlling it.

### Covert Channel
A communication method that hides information inside traffic that appears legitimate.

### DNS Resolver
A system that receives DNS queries and helps find the IP address associated with a domain.

### Authoritative DNS Server
A DNS server responsible for providing authoritative information about a domain.

### DNS TXT Record
A DNS record type capable of storing text data and sometimes abused for tunneling.

## Key Takeaways

- DNS is usually allowed because it is essential to normal network operation.
- DNS tunneling abuses this trust.
- Data can be encoded into DNS subdomains.
- DNS responses can also carry information back.
- DNS tunneling can be used for data exfiltration.
- Malware can use DNS tunneling for command and control.
- Long random-looking domain names can be suspicious.

- Many strange subdomains belonging to one domain can be suspicious.

- DNS tunneling is an example of a covert channel.

- Security requires prevention, detection and response.
