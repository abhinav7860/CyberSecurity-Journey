## 1. Find the Target

I started with network discovery:

```bash

```

I found the DC:2 VirtualBox machine on the local lab network.

For this README, the target IP is written as:

```text

```

### Why did I do this?

Before attacking anything, I need to know **which machine is the target**.

Think of it like looking around a room and asking:

> "Which computer am I supposed to investigate?"

## 2. Scan the Target

Once I had the target IP, I ran:

```bash
nmap -A -sV <DC2_IP>
```

The important result was:

```text

```

Nmap also showed that the website wanted to redirect to:

```text

```

### What does this mean?

Port `80` is normally used for HTTP.

So I knew:

```text

  ↓

  ↓
Web server
  ↓
Investigate the website
```

# 6. Use CeWL to Create a Custom Wordlist

I ran:



### What is CeWL?

CeWL means **Custom Word List generator**.

It visits a website and collects words from its content.

Think of it like this:

```text
Website
   ↓
CeWL reads the words
   ↓
Creates a list
   ↓

```

### Why did I use it?

The flag specifically hinted that a normal wordlist probably wouldn't work.

So instead of using a huge generic list, I created a wordlist based on **this particular website**.

# 14. Understand and Change PATH

The important discovery was that the PATH was restricted.

Originally:

```text
/home/tom/usr/bin
```

So when I typed:

```bash
whoami
```

Linux searched that directory for the `whoami` program.

It wasn't there.

I changed the PATH with:

```bash
export PATH=/bin:/usr/bin:$PATH
```

Now:

```bash
echo $PATH
```

showed:

```text
/bin:/usr/bin:/home/tom/usr/bin
```

I could now run normal commands such as:

```bash
whoami
```

which showed:

```text
tom
```

### Important thing I learned

Changing PATH **did not change my user**.

I was already Tom.

It only changed **where Linux looked for commands**.

For example:

```text
Before:

PATH
 ↓
/home/tom/usr/bin
 ↓
whoami not found


After:

PATH
 ↓
/bin
 ↓
/usr/bin
 ↓
/home/tom/usr/bin
 ↓
whoami found
```

# 18. Check Jerry's Sudo Permissions


### What does `sudo -l` do?

It lists what the current user is allowed to run using `sudo`.

In this case:

```text
Jerry

   ↓
```

This was the privilege-escalation opportunity.

# What I Learned

### Recon
I learned that I should identify the target and its exposed services before trying to exploit anything.

### Wordlists
A wordlist is simply a list of possible values. CeWL helped me create one specifically from the target website.

### WordPress Enumeration
WPScan helped me identify WordPress users and test the custom wordlist against them.

### Port Enumeration
Scanning all ports was important because SSH wasn't running on the normal port 22.

### Restricted Shells
Tom was placed inside `rbash`, which limited the commands available through his PATH.

### PATH
I learned that PATH controls **where Linux searches for commands**. It does not determine which user I am.

### `su`
`su` allowed me to switch from Tom to Jerry using Jerry's credentials.

### `sudo -l`
This showed me exactly what Jerry could execute with elevated privileges.

### Privilege Escalation
The dangerous sudo rule was:

```text
(root) NOPASSWD: /usr/bin/git
```

That allowed me to use Git's functionality to obtain a root shell.
